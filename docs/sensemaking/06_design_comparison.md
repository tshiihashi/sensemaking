# 方式比較と、試行できる最小構成

[索引へ](00_index.md) · [元の課題](../../data_analysis_reporting_challenges.md) · [既存の設計案](../systemization_of_knowledge/05_agent_reporting_design.md)

**このファイルは文献を基にした応用案である。** 方式間の評価値、フィールド、手順、完了条件は本資料で設けた。論文がそのまま検証した製品仕様ではない。

## 1. 方式を比較する

同じ情報を保存しても、探索・比較・執筆の負担は異なる。以下は[表現変更の議論](02_process_and_representation.md)、[主張と出典の接続](03_claims_evidence_and_synthesis.md)、[形式化・曖昧さの研究](04_ambiguity_formalization_and_provenance.md)を踏まえた設計上の比較であり、同一条件の実験結果ではない。

| 候補 | 見逃しへの対応 | 情報過多への対応 | 横断関係・複数解釈 | 導入負担・弱点 |
| --- | --- | --- | --- | --- |
| 文書ごとの要約と検索 | 語が分かれば戻れるが、未命名の現象を拾いにくい | 入口は短いが、要約時に情報を落とし得る | 同じ条件での主張比較を別途行う必要 | 初期負担は小さい。文書をまたぐ比較が手作業になる |
| 論点別の比較表 | 対象・指標・条件の空欄を確認できる | 比較軸が定まれば把握しやすい | 支持・反対・条件差を並べやすい | 軸の選定が必要。多段階・多対多の関係は表が増える |
| 型を定めた主張・根拠グラフ | 既存ノードから関連をたどれる | 局所表示は可能。全体表示は密になり得る | 複数関係と出典を明示できる | 型づけと維持の負担。接続されていない知見の発見は別問題 |
| ノートから段階的に構造化し、複数表示を使う | 未分類メモを残し、確認範囲も一覧にできる | 用途別の表・文章・局所図へ投影できる | 構造化済みの部分と保留部分を併存できる | 昇格・統合・改訂の手順が必要。未分類の滞留は残る |
| 形式的な論証モデル | 与えた論証とattackを規則的に検討できる | 結論候補を計算しても説明が別途必要 | 意味論に基づく受容集合を扱える | attackの定義、意味論、入力品質の負担が大きい。基本モデルでは支持や確率は別設計 |

### 推奨と条件

[調査に基づく判断] **初期候補は「原資料を保持するノート＋論点別比較表＋必要部分の関係記録」とする。** 文章で読め、表で比較でき、複雑な関係だけ局所的に図示できる形から試す。共有する対象・条件・IDは揃えるが、全メモに最初から厳密な分類を求めない。P04の接続方法、P08の形式化への注意、P12の導入経験が着想源である。

ただし、問いと比較軸が固定されているなら表だけで始める方が負担が小さい。多段階の根拠連鎖や再利用が頻出するなら、関係の型を増やす余地がある。形式的な受容計算が業務要件になる場合にP13を検討する。

## 2. 最小の保存構造

Markdownと表で試せる。以下は論理上の区分であり、最初から別DBやノード種類を大量に実装する必要はない。

| 区分 | 最低限持つ情報 | 必要になったときの追加 |
| --- | --- | --- |
| Source：元の成果物 | ID、場所、版、具体的な参照位置 | データ・コード・実行条件、ハッシュ、利用上の制約 |
| Note：記録単位 | ID、本文、出典または「出典未確認」 | Observation／Hypothesis等の型、対象・期間・比較条件、作成者 |
| Relation：関係 | 始点、終点、関係の意味または「未整理」、理由 | 根拠、成立条件、提案者、確認状態、改訂情報 |
| Change：改訂記録 | 変更前後、変更の契機、日付 | 影響するNote・Relation・レポート |
| View：読者向け出力 | 読者の問い、使用ID、主要な限定条件 | 比較表・図、除外理由、詳細・保留事項へのリンク |

Relationは単なる線ではなく、「この条件で、この根拠から、その主張に対してどう位置づけたか」という判断である。自動抽出した関係には提案状態を付け、確認済みの関係と区別する。

### 運用上の判断基準

- **観察と解釈**：計算・図表から確認できる記述と、機序や意味の説明を区別する。Observationという型を付けても正確さを保証しない。
- **比較可能性**：対象、期間、指標定義、分母、集計、データ版を確認してから支持・反対を付ける。未確認なら比較保留を許す。
- **根拠の依存**：同一データ・同一原典の再利用は依存関係として残す。ノートや引用の個数を証拠の強さに直結させない。
- **関係の強さ**：「関連がある」「説明と整合する」「代替説明を除外した」を区別する。支持関係を自動的に推移させない。
- **更新**：旧版・保留理由を参照可能にし、新しい情報で影響する主張と出力を点検する。訂正、撤回、適用範囲の限定、解釈の変更を区別する。
- **自動化**：AIによる類似・関連候補の抽出と、支持・反証の確定を分ける。修正された候補の出典と理由を残す。

## 3. 入力から出力まで

1. **問いと範囲を決める。** 読者、対象、利用目的、入力資料を列挙する。不明な条件は仮定にする。
2. **元資料を登録する。** SourceのIDと版を決め、読む範囲・未確認範囲を分ける。本文の要約だけを唯一の記録にしない。
3. **観察・疑問を拾う。** 自由記述で残し、再利用・比較に必要なものからIDと条件を整える。
4. **論点別に並べる。** 条件を比較し、重複、整合、不一致、比較不能、保留を記す。関係が複雑な箇所だけ図にする。
5. **解釈を比較する。** 各仮説の支持、説明できない結果、前提、識別に必要な追加観察を並べる。根拠の弱い説を形式的に同格にしない。
6. **読者向けに編集する。** 主要な答えに加え、判断を変え得る反証・条件を本文へ置く。比較表や出典へ戻れるリンクを付ける。
7. **新しい結果が来たら影響先を確認する。** 既存観察、関係、仮説、出力のどれが変わるかを記録し、必要なら解析・読解へ戻る。

出力は、短い入口、論点別比較、元資料へ戻れる記録、未確認事項と次の検証である。単一の仮説を選ぶこと自体は完了条件にしない。

## 4. 小さな例：集計差を因果の証拠にしない

**以下はすべて説明用の架空データである。** 実際の顧客・施策の結果ではない。

### 入力

同じデータ `D1-v1` を使う2本のレポートを考える。金額は説明用の売上単位。両群100人で、施策を受けたかどうかの割付方法は不明とする。

| 顧客層 | 施策群：人数×平均 | 比較群：人数×平均 |
| --- | ---: | ---: |
| 高売上層 | 90×100 | 10×100 |
| 低売上層 | 10×20 | 90×20 |
| 全体平均 | 92 | 28 |

- R1-v1：全体の比較を掲載。表の全体平均は施策群92、比較群28。
- R2-v1：同じデータの層別結果を掲載。各層では両群の平均が等しい。

### 保存する内容

| ID | 種類 | 内容・出典 |
| --- | --- | --- |
| O1 | Observation | 全体平均は92対28。Source：R1-v1、全体表。D1-v1に依存 |
| O2 | Observation | 層別の平均は高層100対100、低層20対20。Source：R2-v1、層別表。D1-v1に依存 |
| O3 | Observation | 施策群では高売上層の比率が高い。Source：R2-v1、人数列 |
| H1 | Hypothesis | 全体差を施策の因果効果で説明できる |
| H2 | Hypothesis | 顧客層の構成差が観測された全体差を説明する |
| Q1 | 未解決の問い | 割付方法、顧客層の定義・測定時点、層内の他要因はどうか |

O1をH1の確証として採用しない。O2はH1の単純な説明を疑う材料、O2とO3はH2と整合する材料として理由つきで記録する。仮説の因果的な確定にはQ1の確認が必要である。

### 読者への出力と更新

「全体では施策群の売上が高いが、同じ顧客層内では差がない。構成差で説明できるため、施策効果の断定は保留する」と示し、O1〜O3とQ1へリンクする。

R1だけを読んだ段階でH1を有力としていた場合、R2を加えた時点でその判断を見直し、変更理由と利用先を記録する。R1を削除したり、O1とO2を同一条件での矛盾として処理したりしない。

[架空例による確認] 全体と層別の観察が同時に成立すること、同じデータを使う2本のレポートが独立した追試ではないこと、解釈を改訂しても旧観察と出典を残せることを確認した。92・28の加重平均は計算で照合した。UIの使いやすさや、利用者の見逃し減少を検証した例ではない。

## 5. 実データで比較するときの確認項目

方式を決める前に、同じ小規模な資料集合で「文書要約＋検索」「比較表」「段階的な構造化」を比較する案とする。順序・習熟の影響を考慮し、利用者評価を行う場合は条件を記録する。

| 観点 | 観測するもの | 避けたい評価の誤り |
| --- | --- | --- |
| 見逃し | あらかじめ用意した重要な例外・条件の発見と未確認範囲 | 「すべてを発見した」という保証に拡大しない |
| 情報過多 | 指定した問いに答える時間、理解の誤り、負担 | 本文の短さだけを成功にしない |
| 横断理解 | 異なるレポートの関係と、その条件を説明できるか | 共起した対象数を理解の量としない |
| 複数解釈 | 複数説と識別条件を根拠つきで示せるか | 仮説の個数だけを増やさない |
| 来歴 | 元の表・条件・版に戻り、訂正の影響先を探せるか | リンクの存在とリンク先の十分さを混同しない |
| 導入・保守 | 初回入力、型の選択、重複統合、改訂に要する手間 | 使い始めだけを測って維持負担を無視しない |
| AI支援を加える場合 | 候補の誤り、見落とし、修正の負担、過剰な支持判定 | 人間向け研究の結果をAIの精度保証に流用しない |

現時点で実施済みなのは文献確認と上の架空例の整合確認まで。実データ、利用者、LLMの比較試験は未実施である。
