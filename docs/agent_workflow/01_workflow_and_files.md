# AI Agentの解析・知識整理・レポート作成：作業と保存ファイルの提案

[索引](00_index.md) · [レビューと修正理由](02_review_and_design_decisions.md) · [課題定義](../../data_analysis_reporting_challenges.md) · [SoK調査](../systemization_of_knowledge/00_index.md) · [Sensemaking調査](../sensemaking/00_index.md) · [読者側の調査](../reader_understanding/00_index.md)

## 1. 提案の要点と位置付け

**Agentは、実行の記録、現在の知見、結果を横断した解釈、読者向けの報告を区別して残す。** 各stepでは短い記録を保存し、データや手法が増えた節目で横断整理を行い、最後に複数の図と1つのMarkdownレポートを作る。知見と横断整理はグループごとの入れ子にでき、内容が分かる名前を付ける。読者向けに整ったMarkdownは、最終レポートへ並列に配置・貼り付けられる部品としても使う。本文に採用しなかった結果も、確認範囲と根拠をたどれる状態にする。

本資料全体は **[応用案・未検証]** である。既存の文献調査を統合し、ファイル配置と更新手順を具体化した。今回、新たな文献調査・原典の再照合・実データでの性能評価は行っていない。研究結果をAgentの性能保証には用いない。

汎用化するのは「問い・対象・条件・根拠・観察・解釈・関係・確認状態」である。生物学、売上分析、システム評価、文献調査などで共通に使い、個別の検定、指標、可視化手法、専門的な関係の種類は対象に合わせて追加する。特定のDB、Agent製品、プログラミング言語は前提にしない。

主な対象は複数データ・複数手法の結果を横断する仕事。単一結果の確認なら後述の最小構成へ縮小する。文献調査では「実行」を検索・読解、「出力」を抽出表等に読み替え、コードがなければ `scripts/` は作らない。

**運用では§5の手順から入り、記録が必要になった時に§6を使い、引き渡し前に§8を確認する。** §2〜4は設計根拠と保存規則。すべての表を毎step埋める指示ではない。各stepでは「今回の問い・実行・観察・確認・次の操作」、節目では「比較と判断の変更」、執筆時には「採用する主張と根拠」を更新する。詳細欄は主要主張、重要な例外、繰り返し使う関係から補う。

### 元の課題に何を足すか

| 課題 | Agentが実施すること | 保存先 |
| --- | --- | --- |
| 注目した現象以外の見逃し | 入力・確認範囲を棚卸しし、予想外・反対方向・未確認も残す | `sources.md`、`analysis_history.md`、`findings.md` |
| 情報過多 | 大量の出力は元ファイルへ置き、知見を選んで構造化し、本文を編集する | `results/` → `findings.md` → `report.md` |
| 結果間の関係が分散 | 論点別に条件をそろえて比較し、関係の理由を記す | `synthesis.md` |
| 複数の妥当な解釈 | 観察と説明を分け、支持・反対・成立条件・識別方法を併記する | `findings.md`、`synthesis.md`、重要部分は `report.md` |

## 2. 文献調査から採ること・採らないこと

以下は既存資料に基づく設計判断。右端の資料から、原典の節・ページと確認範囲へ戻れる。

| 採る考え方 | 本案での具体化 | 根拠と適用上の注意 |
| --- | --- | --- |
| 発見・保存・伝達を往復する | 執筆中の根拠不足を次の解析課題へ戻す | [SoKのモデル整理](../systemization_of_knowledge/01_overview_and_model.md)。循環モデルからの応用で、固定工程の効果検証ではない |
| 問いからの検証と結果からの探索を往復する | 結果を見る前の期待、発見後の説明、仮説を区別する次の観測を分ける | [Pirolli & Card、Sachaら](../sensemaking/02_process_and_representation.md)、[SoKのtop-down探索・偽発見の議論](../systemization_of_knowledge/04_future_directions_and_limits.md)。統計手法そのものは個別に設計する |
| 分類に収まらない情報から表現を見直す | 未分類・未説明が判断に関わる時、比較軸・グループ・問いを改訂する | [Russellら、residueと表現変更](../sensemaking/02_process_and_representation.md)。フォルダ分割だけでは代替しない |
| 必要になった部分を構造化する | 当初は出典付きメモでよく、比較・再利用する知見からカード化する | [Shipman & Marshall、P08](../sensemaking/04_ambiguity_formalization_and_provenance.md)。形式化の負担への対応 |
| 原資料と判断の来歴を結ぶ | 入力版・実行・出力・観察・報告の参照をつなぐ | [Xuら、P07](../sensemaking/04_ambiguity_formalization_and_provenance.md)。来歴を残すだけで正しさは保証されない |
| 曖昧さと条件差を保持する | 比較保留と競合仮説を許し、単一の確信度にまとめない | [Nowak & Bartram、P06](../sensemaking/04_ambiguity_formalization_and_provenance.md)。専門家の限定された課題からの示唆 |
| 主張と根拠を対応させる | 知見IDから具体的な表の行・図の箇所・出典の節へ戻す | [主張・根拠・研究ノートの調査](../sensemaking/03_claims_evidence_and_synthesis.md)。引用の存在だけでは内容の裏付けにならない |
| 読者の理解と信頼を分ける | 主要な条件を主張の近くに置き、根拠まで実際にたどる | [読者向け編集案](../reader_understanding/03_report_design.md)、[信頼・検証研究](../reader_understanding/02_trust_and_verification.md)。読みやすさや納得感だけで評価しない |
| 関係の意味と測定条件を保つ | 相関、所属、因果、説明の支持を区別し、分野固有項目を追加する | [生物学・創薬の統合整理](../biomedical_sensemaking/03_synthesis_and_research_log.md)。他分野への転用は本案の判断 |

全面的な知識グラフ化、全出力のカード化、すべての知見対への関係付けは初期要件にしない。論点が固定なら比較表だけでもよい。多段階の根拠連鎖を繰り返し使う場合だけ関係表や局所図を増やす。この選択は[既存の方式比較](../sensemaking/06_design_comparison.md)に沿うもので、グラフの優劣を一律に決めるものではない。

## 3. 標準のファイル構成

以下は**これから行う個々の解析案件の作業ルート**の例であり、このリポジトリに空ファイルを一括作成する指示ではない。既存のNotebook・実行管理・フォルダ構成が同じ役割を持つなら参照を使う。

```text
<作業ルート>/
  brief.md                 # 問い、読者、範囲、仮定、完了条件
  sources.md               # 入力・外部知識の所在、版、定義
  analysis_history.md      # stepごとの実行・確認・次の問い（追記）
  findings/
    index.md               # グループ一覧・重要な例外・未分類への入口
    未整理メモ.md
    売上/
      index.md
      顧客層別/
        index.md
        顧客層ごとの平均売上比較.md
        施策群と比較群の顧客構成.md
      地域別/
        index.md
        地域ごとの売上推移.md
  synthesis/
    index.md               # 主要な問い・現在の判断・グループへの入口
    確認範囲.md
    レポート構成.md         # 採用ファイル・順序・確認した版・配置先
    施策評価/
      index.md
      売上差の説明/
        index.md
        全体差と顧客構成の関係.md
        施策効果を判断するための追加確認.md
  report.md                # 読者に渡す1つのMarkdownレポート
  scripts/                 # 解析・図生成コード
  results/
    全体売上比較_run-001/    # 実行単位の表、図、ログ等
    顧客層別比較_run-002/
    figures/               # レポート用の図（元結果と生成実行へ接続）
```

これは売上分析を例にした配置であり、グループ名・深さ・作成するファイルは案件に合わせる。**以下の `findings.md`・`synthesis.md` という表記は、小規模時の単一ファイルと、分割後の対応するディレクトリ内の文書群の両方を指す略記**とする。分割後は各情報の実在パスへリンクする。

`analysis_history.md` は既存の `analysis_history` の具体名の一案。時系列の「何をしたか」を担う。`findings.md` は現在有効な「何が分かったか」、`synthesis.md` は「複数の結果から何を言えるか」を担う。履歴を全て読み直さなくても現状へ到達できるようにする。リポジトリ自体の編集履歴である `work_logs/` とは別物である。

### 各ファイルに保存する情報と更新時期

| ファイル | 最低限の情報 | 更新するタイミング |
| --- | --- | --- |
| `brief.md` | 目的・主要な問い、読者の判断と予備知識、対象・対象外、制約、仮定、完了条件 | 開始時。目的や対象が変わったら変更理由付きで更新 |
| `sources.md` | 入力ID、所在、版・取得時点、対象・期間・単位・指標定義、制約、外部知識の確認範囲 | 入力追加・訂正時。生データは複製せず所在を参照 |
| `analysis_history.md` | 実行ID、目的、入力版、コード・条件、出力、成功・失敗、実際の確認、知見ID、次の問い | 出力を得た各stepの終了時。失敗も短く記録 |
| `findings.md` | ID索引、観察と条件、具体的根拠、確認済みの範囲、制約、関連する問い、未分類メモ | 意味のある結果、例外、疑問を得た時。訂正時 |
| `synthesis.md` | 確認範囲、論点別比較、仮説、根拠の依存、未解決事項、本文の採否と理由、変更の影響先 | データ・手法の追加後、重要な不一致の発生時、執筆前後 |
| `report.md` | 問いへの答えと条件、複数の図・説明、横断関係、別解釈、限界、詳細への参照 | 横断整理後に草稿。検証や更新に合わせて改訂 |
| `scripts/`・`results/` | 実行可能なコード、取得した出力、必要な実行条件・ログ | 各実行時。引用中の過去出力を上書きしない |

### 小さく始め、大きくなったら分ける

- **最小構成**：`analysis_history.md`、`findings.md`、`report.md` と実際のコード・出力。`findings.md` 内に前提、入力、比較、未解決事項の節を置く。役割を区別できればファイルを分けなくてよい。
- **標準構成**：上の構成。複数データ・複数手法を横断する今回の中心的な利用場面では、比較を独立して読めるようにする。
- **拡張構成**：知見一覧から目的の項目を探しにくい、編集が衝突する、Agentが毎回全文を読む必要が出る場合、意味のあるグループを入れ子にする。履歴も必要なら `analysis_history/顧客層別の売上を比較_run-002.md` のように分割する。単一ファイルから移行する時は、元の一覧を新しい索引への案内にし、参照元を更新する。件数の固定閾値は設けない。

表が大きくなればCSV等に移してよい。その場合、列定義を添え、Markdownは表への参照と判断の説明にする。Markdown表とCSVを独立した正本として二重更新しない。

### 入れ子のグループと索引の運用

- `findings/` は対象・現象・データ群など、観察を探しやすい軸でまとめる。`synthesis/` は読者の問い・判断・説明候補など、横断比較を探しやすい軸でまとめる。両者の階層を同じにする必要はない。
- グループ内でさらにまとまりが生じたらサブディレクトリを作る。分割単位は一つの観察または論点を条件・根拠とともに読める範囲とし、文字数だけで切らない。深さは固定しないが、目的の文書へ到達する手間が増えるだけの階層は作らない。
- 各グループの `index.md` は「扱う範囲」「直下の文書・子グループへのリンクと短い要旨」「重要な例外・保留・未確認」を持つ。親索引へ全子孫の詳細を複製しない。グループ自体の解釈が長くなるなら、説明的な名前の別ファイルへ分ける。
- 一つの知見が複数グループに関わる場合、正本は一か所に置き、他の索引からリンクする。配置上の所属を、科学的・論理的な関係そのものとみなさない。
- Agentは全体索引→関連グループの索引→必要な文書→元結果の順に読む。節目では他グループの要旨、重要な例外、未整理メモ、確認範囲も見直す。関心のあるグループだけを見続けない。
- ファイルの追加・移動・改名と同時に、親索引と参照元を更新する。グループ境界をまたぐ比較は `synthesis/` の論点にまとめ、関係する複数グループからたどれるようにする。

### 内容が分かるファイル名を付ける

`F-001.md`・`Q-001.md` のような記号と数字だけの名前は使わず、**対象＋比較・現象・問い**が分かる名前にする。日本語でも英語でもよいが、案件内では用語と表記をそろえる。

| 用途 | 名前の例 |
| --- | --- |
| 観察 | `顧客層ごとの平均売上比較.md`、`測定条件ごとの信号強度.md` |
| 横断整理 | `全体差と顧客構成の関係.md`、`測定法による結果の不一致.md` |
| 未解決事項 | `施策効果を判断するための追加確認.md` |
| 実行履歴 | `顧客層別の売上を比較_run-002.md` |

結論が変わりやすい段階では、`施策が売上を増加させる.md` のように未確定の結論を名前に固定せず、比較対象・問いを名前にする。同名を区別する必要がある時は条件・期間を追加し、それでも必要な場合だけIDや実行番号を添える。表示順は索引とレポート構成で指定し、連番をファイル名の主な意味にしない。

## 4. 共通の記録ルール

### IDと参照

作業内で一意のIDを使う。例：問い `Q-001`、入力 `S-001`、実行 `A-001`、観察 `F-001`、仮説 `H-001`。IDは改名・並べ替え後も維持し、再利用しない。単なる一時メモには必須とせず、他から参照する時に付ける。

**IDとファイル名は別の役割を持つ。** 名前は人が内容を見分けるため、IDは改名・移動後も同じ記録を追うために使う。IDは文書内の管理情報または索引に置き、ID→現在のパスを索引で解決できるようにする。読者向け本文はIDだけの参照にせず、内容が分かるリンク名を使う。

参照の連鎖は、`report.mdの主張 → F/H → 出力の該当箇所 → A → コードとSの版`。IDだけで終わらず、相対リンクと表の列・行キー・図のパネル・PDFのページ等を添える。別案件を統合する場合は案件名も付けて衝突を防ぐ。

数値の正本は `results/`、入力定義の正本は `sources.md`、観察の正本は `findings.md`、解釈・関係の正本は `synthesis.md` とする。レポートに値を再掲する時は照合する。巨大な表の全行を知見カードへ転記しない。

### 不明と確認済みを分ける

- 確認状態は「出力を確認」「元データと照合」「独立データで確認」など、実施した行為と範囲で記す。Agentの自己評価を独立検証と呼ばない。
- 掲載状態（本文・詳細・保留・対象外）は確認状態と分ける。詳しく確認した結果でも本文に不要な場合がある。
- 「未解析」「実行失敗」「出力未確認」「確認したが明確な差なし」「比較不能」を別扱いにする。空欄を差なしと読ませない。
- 不確実性は、推定のばらつき、欠損・未測定、比較条件の違い、競合する説明に分ける。架空の確率や総合確信度で埋めない。
- 主張の役割も分ける。記述的な観察、説明・一般化の仮説、次の行動の提案を識別し、提案には目的・判断基準・制約を添える。「説明として有力」と「その行動を選ぶべき」は別の判断である。
- 保存するのは操作・結果と説明可能な判断理由であり、内部思考の逐語記録ではない。

## 5. Agentが実施する作業

### 開始時：問いと入力を確認する

1. 既存の依頼・成果物を読み、`brief.md` に読者が説明・比較・判断できるべきことを記す。予備知識、読む時間、探索／事前仮説の確認／選択肢の比較という用途も区別する。不明点は仮定とし、作業できる部分から進める。
2. 主要な問いについて、何が分かれば答えになるか、どの条件なら答えを変えるかを仮置きする。結果を見る前の期待と、既に結果を見て作った説明を区別し、後者を事前仮説へ書き換えない。判断基準が不明なら順位を確定せず、条件別の比較を成果物にする。
3. `sources.md` に入力と外部知識を登録する。対象ID・指標・単位・期間だけでなく、測定対象、独立した観測単位、共有する試料・前処理・参照DBを確認する。対応が曖昧なら同一対象へ強制統合しない。外部知識は確認した箇所と適用条件を記し、今回のデータの直接証拠と区別する。
4. `synthesis.md` の確認範囲に、問いに必要なデータ×方法×条件と、結果内で見る範囲を置く。全体傾向、部分集団、反対方向、明確な差なし、欠損・未測定のうち何を見るかを決める。総当たりは求めず、対象外には理由を付ける。

開始時の出口は「次の解析で答える問いと、答えを制約する前提が分かる」こと。完全な仮説一覧を作るまで実行を止めない。[根拠となる既存整理：探索と検証](../sensemaking/02_process_and_representation.md)、[ドメイン情報とtop-down探索](../systemization_of_knowledge/04_future_directions_and_limits.md)。

### 各step：実行と観察を保存する

1. 今回答える問い、探索か確認か、入力版、対象・選択条件を決める。仮説の確認なら予想する観察と、それと異なった場合に見直す判断を実行前に短く書く。コードを `scripts/`、出力を新しい実行IDの `results/` に保存する。
2. 成否と出力の妥当性を確認する。入力件数と除外後の件数、単位・分母、欠損、解析単位、手法の前提を主要主張に必要な範囲で照合する。既知の出力誤りは修正するか使用対象から外し、未確認の出力を確定した観察として使わない。
3. ランキング上位だけで候補を拾わず、選んだ範囲の全体分布、反対方向、条件別の例外、差が明確でない結果も見る。全表を保存したことを全行確認済みとしない。絞り込み条件、表示・抽出した範囲、未確認部分を履歴か確認範囲表へ残す。
4. 主な結果、反対方向、重要な例外、解釈できない結果を `findings.md` に残す。候補化の理由は「問いに答える」「結論を変える」「現在の説明で扱えない」等とする。未整理なら出典付き短文でよい。似た結果はまとめても、条件・方向が異なるものを消さない。
5. `analysis_history.md` へ実行・実際の確認・観察・次の操作を短く追記する。探索で選択条件や閾値を変えた場合は、その変更と選択への影響も残す。全端末出力はログへのリンクでよい。
6. 再利用・比較・本文の根拠にする時にカード化し、次表の必要な確認を補う。追加確認ができなくても記述的な観察は残し、一般化や原因説明の範囲を制限する。

| 主張に使う際の確認 | Agentの操作と残す判断 |
| --- | --- |
| 計算と出典の整合 | 主張の値・対象・条件を元表と照合。失敗出力や別版を混ぜた場合は影響先を再確認待ちにする |
| 探索による選択 | 候補集合・比較範囲・選択後の条件変更を確認。多重比較等への対応は解析設計に即して選び、未対応なら一般化の制約として記す。補正法を一律に固定しない |
| 感度と再現の違い | 合理的な前処理・集計・閾値の変更で主張が変わるかを必要時に確認。同じデータでの頑健性確認と、新しい独立データによる確認を分ける |
| 「差なし」の意味 | 効果量や区間、情報量等を確認できる範囲で見る。有意でないこと、未測定、同等性を示したことを混同しない |
| 対象領域への適用 | 外部知識の対象・時点・測定法が今回に適合するか確認。不一致なら背景知識のまま保持し、今回の機序の実証へ昇格しない |

これらは[SoKを踏まえた品質確認案](../systemization_of_knowledge/05_agent_reporting_design.md)と[生物学の分類・説明の区別](../biomedical_sensemaking/02_empirical_studies.md)を操作へ落としたもの。個別の統計解析の正しさを、この共通手順だけで保証しない。

### 節目：全体を横断して見直す

新しいデータ・手法の追加、重要な不一致、未分類の滞留、執筆開始を契機に、次を行う。出口は「各主要問いに対する現在の判断・限界・次の操作」であり、単に比較表が埋まった状態ではない。

**a. 確認範囲と比較可能性を点検する。** 他グループの要旨、未整理・保留、未確認範囲を読み直す。論点別に対象、期間、指標、分母、集計、測定法、入力版を照合し、比較可能／条件付き／比較不能を理由付きで決める。比較不能な結果にも別の論点への寄与はあり得るため、削除しない。

**b. 関係の意味と根拠の依存を確認する。** 一致・補完・重複・例外・不一致を、何の主張に対する関係かとともに記す。同じ試料・入力、共通する前処理・注釈資源、同じ原著を引用する複数文献をまとめて確認し、方法や引用の本数を独立な支持の数にしない。別手法で同じ傾向が出た価値と、共有する偏りが残ることを併記する。

支持のつながりを自動で推移させない。「結果が機序と整合する」「背景文献がその機序を別条件で示す」だけから、今回の対象でも機序が成立すると結論しない。重要な説明では、**観察 → 解釈に必要な前提・外部知識 → 主張**を一文または短い関係表にし、未確認の接続を特定する。多段階の説明は、その接続の不確かさを最終主張にも引き継ぐ。[既存の関係・依存の規則](../sensemaking/06_design_comparison.md)、[分野固有の関係と不確実性](../biomedical_sensemaking/03_synthesis_and_research_log.md)。

**c. 仮説を識別する観測を決める。** 成立し得る説明ごとに、支持、反対・未説明、必要な前提、正しければ期待される観察を並べる。説明同士が排他的か、併存するか、条件によって切り替わるかも記す。各結果が複数説に同じように整合するなら、それだけでは識別できないと記す。「反対」とする時は、仮説が何を予測し、その結果を検出・比較できる条件だったかを確認する。根拠の薄い説を形式的に同格にしない。

次の操作は「有力説を補強する結果が増えるか」だけで選ばず、**結果がAならどの判断を変え、Bなら何を保留するか**を書いて選ぶ。両方で判断が変わらない操作は、基礎的な品質確認等の別の目的がなければ優先度を下げる。新情報で旧仮説を弱めることも成果とする。[探索・検証の往復](../sensemaking/02_process_and_representation.md)、[複数解釈の保持](../sensemaking/04_ambiguity_formalization_and_provenance.md)。

**d. 収まらない結果から問い・分類・表示を見直す。** 未分類を永久に置くだけで済ませない。主要主張に関わる例外が今の分類では説明できない時や、同じ比較のために多数の文書を往復する時は、次の小さな変更を試す。

- データ・手法別の一覧を、現象×対象条件の比較表へ組み替える。
- 全体だけのまとめを、部分集団・時点別へ分ける。
- 経路への所属、共変動、介入結果など、異なる関係を分ける。
- 多段階の説明に限って、根拠と未確認の接続を示す局所図を使う。

別の表現で重要な例外と関係を説明できるか確認し、改善がなければ元へ戻してよい。改訂理由とID対応を残し、結果の方を分類に合わせて書き換えない。これは[residueからの表現変更](../sensemaking/02_process_and_representation.md)の応用であり、ディレクトリを細分化する指示ではない。

**e. 次の操作と停止理由を決める。** 判断への影響、仮説を見分けられる見込み、実行可能性、費用で選ぶ。必要情報がない、識別できる操作が依頼範囲を超える、追加結果で今回の判断が変わる見込みが小さい場合は、制約と再開条件を記して停止する。根拠不足の主張を確定する理由にはしない。

| 状況 | 次の動作 | 必ず残すもの |
| --- | --- | --- |
| 値や条件が原出力と合わない | 原出力・コードへ戻り修正、または主張を外す | 原因、訂正、影響先の状態 |
| 結果間の条件が違う | 対応付けを調べるか、条件別に報告 | 比較できる範囲と残る差 |
| 同じ観察に複数説が残る | 識別できる確認を実行、できなければ併記 | 仮説ごとの予想、判断が変わる条件 |
| 重要な結果が分類に収まらない | 問い・比較軸・表現を見直す | 変更前後の対応と判断への影響 |
| 優先順位が目的次第で変わる | 目的・評価基準別に選択肢を比較 | 観察とは別の価値判断・制約 |
| 重大な不足が依頼者にしか解決できない | 必要な情報だけ確認し、独立に進められる作業を続ける | 未確定の判断と回答による分岐 |

### 執筆時：主張と図を組み立てる

1. `synthesis.md` に本文へ採る知見と詳細へ回す知見、その理由を記す。**知見の集合として**問いへの回答、適用条件、重要な例外、横断関係が揃うか確認する。似た主張の繰り返しを減らし、判断を変える例外・制約を優先する。根拠が弱くても判断に重大なら「重要だが未確認」として残す。目立つ結果・確かな結果だけの上位順にしない。
2. 図ごとに、読者に理解してほしいこと・避けたい誤解、対応するF/H、元出力、比較条件を決める。全体傾向、条件別比較、重要な例外など、異なる役割の図を組み合わせる。横断関係は共通軸の比較表や局所図としても示し、別々の図の説明を読者が頭の中で統合することだけに頼らない。比較パネルでは軸・尺度・色の対応をそろえるか、違いを明示する。
3. 図を生成し、`results/figures/` に保存する。図生成も実行として履歴に残し、使用した表とコードへ接続する。
4. `report.md` を「要点と限定条件 → 対象・方法 → 論点別の図と説明 → 横断的な結論 → 未解決と次の確認 → 詳細参照」の順を基本に作る。章数は固定しない。読者向けに整った文書は、後述の本文部品として並列配置または貼り付けに使う。採用するファイル・範囲・順序・版は `synthesis/レポート構成.md`（単一ファイル時は本文・図の選択節）に記す。
5. 主張の近くに比較対象・値・条件・重要な限界を置く。図の軸・単位・凡例・集計・不確実性と文章を照合する。根拠不足が見つかれば追加解析するか、主張の範囲を狭める。
6. 読者の予備知識に合わせて用語を説明し、短縮・言い換えの前後で対象・条件・確実性が変わらないか照合する。要約だけでも「何が言えるか／言えないか／何で判断が変わるか」が読み取れるようにする。
7. 主要主張ごとに「結果と限界を説明する」「別結果との関係を説明する」「根拠の具体箇所へ戻る」という確認課題を作り、本文と参照先から答えを復元できるか点検する。人に試していなければ編集上の点検とのみ記し、読者の理解確認済みとしない。

採否は[SoKの集合としての選択基準](../systemization_of_knowledge/05_agent_reporting_design.md)、提示と点検は[読者向け編集手順](../reader_understanding/03_report_design.md)に基づく応用案。資料の短さ、主観的な納得感、実際の理解を別に評価する。

### 更新・再開時：変更の影響先を確認する

新しい版は旧出力へ上書きせず保存する。訂正前後の値・理由・置換先を履歴に残し、旧知見は「訂正済み」「撤回」「適用範囲変更」等で識別する。入力や条件が変わった観察には新IDを与え、同じ観察の誤記訂正はIDを維持して改訂記録を残す。

変更したS/A/F/H・関係を参照する仮説・関係・図・本文を検索し、そこから参照される要約や行動提案までたどる。再確認が終わるまで影響先を「再確認待ち」にする。関連IDは本文・図生成記録にも残し、ID検索で影響先を探せるようにする。単なる新しい版の到着を旧仮説への反証と扱わない。値が同じでも、外部知識・前提・読者の判断基準が変わった場合は解釈と提案を見直す。

作業再開では、`brief.md`、知見索引、`synthesis.md` の現在の判断・未解決事項、直近の履歴を先に読む。詳細なコード・出力は今回の問いに必要なものをたどる。

### レポートに直接使えるMarkdownを育てる

最終レポートに複数のMarkdownを並列に配置・貼り付けられる利用形態を前提に、**一部の `findings/`・`synthesis/` 文書を、そのまま読者に渡せる本文部品として整える。** 個々の結果説明には `findings/`、複数結果をつなぐ説明には `synthesis/` の文書を使う。すべての途中メモを完成した文章にする必要はない。

| 文書の用途 | 書き方 | レポートへの使い方 |
| --- | --- | --- |
| 作業メモ | 短文・箇条書き・未整理を許す。出典と未確認状態は残す | 直接掲載せず、必要になった時に整理 |
| 本文部品 | 対象・問い、観察、図表、根拠、解釈、重要な条件・限界を自立した説明にする | 文書全体を配置・貼り付け可能 |
| 本文と管理情報の混在 | 冒頭に完成した本文、末尾に明示した管理情報を置く | 明示した本文範囲だけを使用 |

用途と掲載準備状態はグループ索引に記録する。「本文部品・配置確認待ち」「本文部品・対象レポートで配置確認済み」のように、どこまで整ったかを示す。**掲載準備状態と科学的な確実性は別**であり、結論を保留する説明も本文部品にできる。

本文部品を書く時は次を守る。

1. **単独でも理解できる。** 冒頭に何を対象として何を比較したかを書く。「上記の結果」「前の図」のような配置依存の表現を避け、必要な前提を短く含める。並列の別文書を読まなくても、主張と適用範囲を理解できるようにする。
2. **根拠と限界を本文内に残す。** 主要な値・図表・出典と、結論を変える条件・反証を同じ部品に含める。重要な限界を管理情報だけに置かない。
3. **管理情報の置き場所を選ぶ。** 全文をそのまま使いたい文書では、ID対応、改訂履歴、採否理由、確認担当等を索引・履歴・レポート構成へ置く。混在させる場合は、次節の本文境界を使う。未解決の科学的内容は読者向け本文にも必要な範囲で示す。
4. **配置を変えても意味が変わらない。** 見出しは内容が分かる名前にし、固定の章番号・通し図番号を前もって付けない。図はまず説明的なキャプションを使い、番号や見出し階層は組み立て時に調整する。本文内参照も一緒に更新する。
5. **正本を一つに保つ。** 読者向け本文を同じ文書で育て、用途別コピーを無制限に増やさない。貼り付けたレポートは特定時点の出力とし、採用元のパス・更新時点または版・本文範囲・配置先をレポート構成に残す。修正は元文書へ反映してからレポートを更新する。

Markdownをリンクしただけでは、その内容が本文に展開されるとは限らない。実際の掲載方法に合わせて、全文配置か、範囲を選んだ貼り付けかを記録する。ここでは特定の表示システムの機能は仮定しない。

**組み立て時は相対パスを確認する。** 深い階層の文書内で有効な画像・資料リンクも、ルートの `report.md` へ貼ると基準位置が変わる。元文書では元文書基準で解決できるパスを使い、貼り付ける時は掲載先基準へ変換する。個別Markdownを配置する仕組みでは、その仕組みがリンクをどう解決するかを確認する。画像・表・脚注・参照形式リンク・見出しアンカーの欠落や衝突も、実際の掲載先で点検する。確認していない配置を「そのまま使える」と断定しない。

複数部品がそれぞれ正しくても、並べると説明の重複や結論の食い違いが生じることがある。最後に全体の導入、部品間の関係、横断的な結論を整え、重要な反証・条件が脱落していないか確認する。

## 6. コピーして使う記録例

以下のコードブロックは雛形。パスは案件内で作成するものの例であり、この資料からの実在リンクではない。

### `brief.md`：問いと判断の前提

```markdown
# 作業の目的

- 読者が説明・比較・判断したいこと：
- 予備知識・説明が必要な概念／読める時間・形式：
- 用途：探索／事前仮説の確認／選択肢の比較
- 対象・対象外／利用できる入力・制約：
- 主要な問いと、答えに必要な観察・比較：
- 現時点の期待・仮定／結果を見る前か後か：
- 行動を提案する場合の目的・判断基準／基準が変わる場合の分岐：
- 今回の完了条件／実行予算・停止条件：
- 変更した問い・前提、その理由と影響先：
```

### グループの `index.md`：階層の入口と管理情報

```markdown
# 顧客層別の売上分析

扱う範囲：施策群・比較群の顧客層ごとの売上と構成。
親グループ：../index.md

| ID | 文書・子グループへのリンク | 要旨・対象条件 | 用途・掲載準備状態 | 確認範囲・更新時点 |
| --- | --- | --- | --- | --- |
| F-002 | 顧客層ごとの平均売上比較.md | 両群の層別平均。期間T | 本文部品・配置確認待ち | 元表を照合／日時 |

## 重要な例外・未確認

- 割付方法は未確認。施策の因果効果は未確定。
- グループをまたぐ比較：../../../synthesis/施策評価/売上差の説明/全体差と顧客構成の関係.md

## 改訂・管理情報

- 文書のID、確認者・確認内容、改訂の契機と履歴への参照。
```

実運用では表中の文書名や親・関連文書のパスをクリック可能な相対リンクにする。子グループはその `index.md` へリンクする。これは索引用の様式であり、全体を読者向け本文として掲載する必要はない。

### 本文部品：`全体差と顧客構成の関係.md`

以下は§7と同じ**架空例**を使った文章例。全文を使う場合は、この内容だけを文書に置き、ID・改訂・掲載管理を索引等へ置く。図は実際に生成・確認したものを本文中へ追加する。

```markdown
# 全体の売上差と顧客構成の関係

この説明用の架空データでは、施策群の平均売上は92、比較群は28だった。
ただし、顧客層ごとに比較すると平均は等しく、群間の顧客構成が異なる。
全体の差だけから施策の因果効果を判断することはできない。

| 比較する範囲 | 施策群の平均売上 | 比較群の平均売上 |
| --- | ---: | ---: |
| 全体 | 92 | 28 |
| 高売上層 | 100 | 100 |
| 低売上層 | 20 | 20 |

売上の値は説明用の単位で、各群は100人。高売上層の割合は施策群90%、
比較群10%である。この構成と層別平均から、全体平均の差を説明できる。
全体と層別の結果は、異なる集計条件で得た両立する観察である。

割付方法と顧客層の測定時点は不明であり、層内の他の要因も検討していない。
施策効果を判断するには、割付と測定条件を確認し、それに合う追加検証が必要である。

根拠：対応する「顧客層ごとの平均売上比較」と「施策群と比較群の顧客構成」。
実案件では、この位置に具体的な出力箇所へ戻れるリンクを置く。
```

## 7. 説明用の小さな例：異なる集計の結果を保持する

**以下は既存の[架空例](../sensemaking/06_design_comparison.md)を使った机上の保存例であり、新しい解析・性能試験ではない。** 全体平均は施策群92、比較群28だが、顧客層別では両群とも高売上層100・低売上層20。施策群は高売上層90%、比較群は10%とする。

| 保存先 | 残す内容 |
| --- | --- |
| `sources.md` | S-001：両群各100人、同じ顧客データ。割付方法・層の測定時点は不明 |
| `analysis_history.md` | A-001：全体集計。A-002：同じ入力を層別集計。各表・コードを参照 |
| `findings.md` | F-001：全体92対28。F-002：各層では平均が等しい。F-003：群間の層構成が異なる |
| `synthesis.md` | F-001とF-002は集計条件が異なり両立する。A-001とA-002は独立データではない。H-001「施策の因果効果」は未確定、H-002「構成差が全体差を説明」は数値と整合。割付等を未解決事項にする |
| `results/figures/` | 図1：全体と層別の平均比較。図2：各群の層構成。各図は元表と生成実行に接続 |
| `report.md` | 「全体では施策群が高いが、同じ層内では差がない。構成差で説明でき、施策の因果効果は判断できない」と図・根拠付きで記載 |

ここで保持すべきものは、全体の観察、層別の観察、構成、因果判断の保留のすべてである。全体結果を削除したり、層別結果を単純な反証として扱ったりしない。

新しい独立データが来たらS-002と新実行を作る。旧観察は残し、Hの評価と本文の適用範囲を見直す。これは対象を実験条件、装置、地域、時期などへ置き換えても使える構造である。

この例だけでは複数データ・複数手法の複雑さを扱いきれないため、[レビュー記録§3](02_review_and_design_decisions.md#3-複数データ複数手法を含む架空例での机上照合)に、共有入力、非有意、未測定、条件差、複数仮説が併存する例も示す。いずれも実データでの検証ではない。

## 8. 完了条件と今後の検証

Agentは次を実際に確認し、結果を `synthesis.md` に残す。

- 主要な問いに、答えまたは判断できない理由がある。
- 主要主張から出力の具体的な箇所、入力版、実行条件へ戻れる。リンクの存在だけでなく値・対象・条件を照合した。
- 確認範囲と未確認範囲を区別し、未分類・保留のうち判断を変えるものを再検討した。
- 全出力の保存と内容確認を混同せず、実際に見た範囲・候補の選択条件・探索後の変更が分かる。主要主張に必要な品質確認を実施したか、未実施に応じて主張を限定した。
- 同じ入力に依存する複数結果を独立な支持として数えていない。比較不能な結果を無理に統合していない。
- 重要な説明では観察から主張への前提と未確認の接続が分かる。複数説に共通する支持を識別の証拠とせず、次の確認と結果別の判断を示した。
- 重要な未分類・未説明の結果について、問い・比較軸を見直したか、現状で保留する理由を記した。行動提案には目的・判断基準がある。
- 重要な反証・例外・代替解釈・限界が本文にあり、要約だけでも過剰な一般化にならない。
- 図と文章の値・単位・対象・比較・方向が一致し、図の生成元が分かる。
- グループ索引から必要な文書へ到達でき、改名・移動後もID対応と参照元が更新されている。名前から対象・比較・問いを判別できる。
- 本文部品は単独で理解でき、管理情報と掲載範囲が区別されている。採用元・版・配置先を記録し、掲載先で画像・リンク・見出し・脚注等を確認した。
- 並列配置・貼り付け後も、部品間で条件や結論が食い違わず、重要な限界が残っている。
- 訂正の影響先を確認し、未解決事項には必要な情報と次の操作、今回停止する理由がある。
- 要約・本文から答えを復元する点検と、実読者による理解・負担の評価を区別し、未実施の評価を明示した。

完了は「すべての知見を発見」「解釈を一つに決定」ではなく、依頼の範囲で根拠と限界を示して報告できた状態とする。

本案の有効性は別途評価が必要である。次の試行では、同じ複数データ・複数手法の課題で、従来の履歴＋レポートと本案を比較する。入力・実行予算・参照可能な資料をそろえ、重要な例外、条件差、依存、未測定、訂正箇所を事前に評価用一覧へ置く。特定仮説の採用を正答にせず、妥当な保留と識別条件も評価する。重要な例外の保持、条件の正確さ、元結果へ戻れるか、訂正の反映、記録時間・維持負担を確認する。読者には「何が言えて、何が言えず、どの結果同士がどう関係するか」を説明してもらい、読みやすさの感想と分けて評価する。提示方法だけを比べる場合は、事実・根拠を固定して配置を比較し、工程全体の改善と区別する。[読者評価の具体案](../reader_understanding/04_evaluation_protocol.md)を参照。

現時点で確認できるのは資料としての整合性までであり、記録負担の減少、見逃しの減少、人の理解向上は未検証である。試行して使われなかった項目は削り、追跡不能だった箇所だけを補う。skill化する場合も、この全資料を毎回読ませるのではなく、短い作業手順と必要時に開く様式へ分ける。
