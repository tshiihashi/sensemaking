# Foresight：比較する候補を、探索できる対象にする

[索引](00_index.md) · [適用例](05_application_and_comparison.md)

Çağatay Demiralp, Peter J. Haas, Srinivasan Parthasarathy, Tejaswini Pedapati. *Foresight: Recommending Visual Insights*. PVLDB 10(12), 1937–1940, 2017。[DOI](https://doi.org/10.14778/3137765.3137813) · [本文PDF](https://arxiv.org/pdf/1707.03877)。

## 1. 何が参考になるか

[調査に基づく判断] 今回もっとも直接使えるのは、「大量の結果を読んで関連を見つける」を、**候補の種類・順位付け指標・検索条件・全体表示**に分ける考え方である。ただし、論文の対象は整形済みの表データにある統計的特徴であり、DEG・CCI・GRNの意味的統合ではない。

## 2. 原典の具体的な仕組み

[原典の整理：§2、PDF pp.2–3](https://arxiv.org/pdf/1707.03877)

入力は行が観測、列が属性の行列。論文のinsightは、分布や関係の統計的特徴が強く現れたものを指す。特徴のクラスごとに候補を順位付けし、図を提示する。本文で具体化する例は次の通り。

| 特徴の型 | 順位付けの指標 | 表示 |
| --- | --- | --- |
| 散らばり | 分散 | ヒストグラム |
| 非対称性 | 歪度 | ヒストグラム |
| 裾の重さ | 尖度 | ヒストグラム |
| 外れ値 | 検出された外れ値の平均標準化距離 | 箱ひげ図 |
| 頻度の偏り | 頻度上位k値の相対頻度の合計 | Pareto chart |
| 線形関係 | Pearson相関係数の絶対値 | 回帰直線付き散布図 |

クラスごとの上位候補を入口に、属性・特徴の強さなどを制約するinsight queryで探索する。相関全体の俯瞰も提供する。全種類を一つの共通スコアへ統合する構成ではない。

[原典の整理：§3–4、PDF pp.3–4](https://arxiv.org/pdf/1707.03877) 計算の高速化にはsketchなどの近似を使う。本文は初期の計算性能結果と利用シナリオを報告する短いデモ論文で、重要な科学的解釈の発見率を測る利用者実験ではない。

## 3. 今回使うには、候補の型を定義し直す

以下は **[応用案・未検証]**。Foresightが実装・検証した機能ではない。

DEG・CCI・pathway・GRNの出力を一つの行列へ押し込むより、既存の結果に対して「どの関係なら候補として拾えるか」を定義する。最初は次のうち問いに関係するものを少数選ぶ。

| 候補の型 | 探す操作 | 候補化後に必要な確認 |
| --- | --- | --- |
| データ間の再現候補 | 対象・比較条件を合わせ、効果方向を比較する | 独立試料か、前処理や対象集団は同じか |
| 条件による反転候補 | 同じ対象を集団・時点・条件別に並べる | 集計方法、分母、交絡、推定の不確実性 |
| 手法間の補完候補 | 同じ細胞型や経路へ対応する異なる出力を探す | 同じ量を測っているのか、説明を接続する追加前提は何か |
| 説明に反する候補 | 現仮説が予想する方向と異なる出力を探す | 未測定・低検出力・条件違いを反証と誤読していないか |
| 特定集団だけの候補 | 全体と部分集団の効果を並べる | 選択後の解析か、十分な独立観測があるか |

「同じ経路名が出た」だけでは一致候補にとどめる。遺伝子集合の重複、活性の方向、測定対象の違いを確認してから説明へ使う。語彙の類似は候補検索に使えても、関係の検証には代用できない。

## 4. insight queryをAgentの操作へ落とす

[応用案・未検証] 一巡ごとに、問い・候補集合・検索条件・次に読む出力を明確にする。以下の例はForesightのAPIや文法ではない。

```text
問い：細胞型Cの経路Pの変化はデータ間で共通か
候補集合：データA/Bの同条件のpathway出力
固定する条件：細胞型C、比較の向き、経路の定義
変える条件：データ、処理条件
拾うもの：方向一致、方向不一致、推定が不明確、対応不能
次の確認：対応するDEGと、対象試料・検出対象の違い
```

局所探索では、Pを固定してデータ・条件を変える。別の一巡では細胞型Cを固定して他経路を探す。最後に、C以外・P以外の出力と未確認範囲へ戻る。近傍の定義を「同じキーワードがある」に固定せず、どの属性を保って何を変えたかを記す。

## 5. 上位候補だけを残さない

[応用案・未検証] 本リポジトリでは、強さの上位k件を本文採用基準にしない。まず次の異なる理由で候補を確保する。

- 大きな効果や繰り返し現れる傾向。
- 主張の適用範囲を変える例外や方向不一致。
- 現在の説明に収まらない結果。
- 重要な問いに関係するが、未測定・比較不能・未確認の範囲。

そのうえで、本文に必要なものを選ぶ。最後の項目は「統計的に目立つinsight」の外にあるが、情報不足を確定した結論として扱わないために必要になる。

全体表示も、巨大な相関行列を作ることが目的ではない。対象×手法×条件の小さな表に、確認済み・未確認・実行失敗・比較不能を区別して置けば、探索の偏りを点検できる。型ごとに候補数を残す場合も、数えた母集合を併記する。

## 6. 近似計算と導入の境界

[応用案・未検証] 大量の候補を近似で絞る必要がある場合、候補探索の結果と、主張に採用する値の確認を分ける。本文へ使う候補は元データまたは正本の出力で照合し、順位の境界付近も必要に応じて確認する。近似で落ちた候補の存在を、後段の再計算だけで回復したことにはならない。

まずは既存の`results/`を検索・比較するところから始める。専用の推薦UI、sketch基盤、全結果への共通ランキングは必須ではない。小規模な結果群なら、これらの構築費用の方が大きい。

## 7. 採用判断

**採る：候補の型を先に明示する、条件を変えて探す、局所から全体へ戻る。** 保存先は既存の`synthesis.md`の比較表・探索メモでよい。

**そのまま採らない：統計的な強さ＝科学的な重要性、上位候補＝確認範囲の網羅、相関＝機序。** 原典は、異質な測定の整合性、多重探索後の科学的検証、複数解釈の保持までを解決していない。
