# EXHYTE：仮説から実行できる確認への接続を点検する

[索引](00_index.md) · [適用例](05_application_and_comparison.md)

Md Musaddaqul Hasib et al. *Unifying AI-assisted scientific discovery around exploration, hypothesis generation, and testing*. Patterns 7(10):101660, 2026。[DOI](https://doi.org/10.1016/j.patter.2026.101660) · [PMC全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC13674306/)。

## 1. 選定上の位置づけ

[調査に基づく判断] 新しい関係をどう発見するかの具体的方法としては、ForesightやRussellらを優先する。本論文は、関係を候補化した後に**どんな確認を実行し、結果から何を更新するか**を点検する補助として有用である。

## 2. 原典の枠組みと根拠

[レビュー著者の整理：The EXHYTE framework / AI methods across the EXHYTE workflow](https://pmc.ncbi.nlm.nih.gov/articles/PMC13674306/)

EXHYTEは次の工程でAI-assisted discoveryのシステムを比較する。

| 段階 | 下位工程 |
| --- | --- |
| EXPLORE | E1：問いの構造化、E2：データ取得、E3：知識の統合・構造化 |
| HYPOTHESIZE | H1：仮説・案の生成、H2：優先順位付け |
| TEST | T1：実験・計算計画、T2：実行・評価・改訂 |

調査対象は2018年〜2025年7月の87本。著者らは仮説から実行可能な検証への移行と、結果を前工程へ戻す接続を主要な不足と捉える。普遍的な科学的方法や完全自動化の標準ではなく、対象システムを記述するレビューの枠組みである。

## 3. 今回は工程名より「受け渡すもの」を使う

以下は **[応用案・未検証]**。7工程に対応する7エージェントや7ファイルを作る必要はない。既存の`findings.md`・`synthesis.md`・`analysis_history.md`間で、次が渡るかを確認する。

| 受け渡し | 足りない状態 | 具体的に残すもの |
| --- | --- | --- |
| 観察→仮説 | 「Pが変化した」から機序Xへ飛ぶ | 仮説Xを考えた観察、追加前提、別の説明 |
| 仮説→優先順位 | LLMがもっともらしいと評価しただけ | 問いへの寄与、検証可能性、必要な費用・情報 |
| 仮説→確認計画 | 「追加検証が必要」で終わる | 比較する対象、入力、手順、出力、競合予測 |
| 計画→実行結果 | 計画を実施済みと扱う | 実行ID、コード、実際の成否と出力 |
| 結果→改訂 | 結果を保存して元の説明を維持する | どの仮説・主張の適用範囲がどう変わったか |

## 4. 使える最小の確認計画

[応用案・未検証] 仮説ごとに「次に調べること」の一文を添えるだけでも、実行条件が曖昧なら進まない。必要な場合は次の形にする。

```text
仮説H1：経路Pの変化は細胞型Cの細胞内変化である
代替H2：全体の変化はCの構成比の違いで説明できる
区別に使う観察：C内の変化と、Cの構成比の変化
入力：試料ごとの発現・細胞型・条件、既存の構成比出力
計画：解析単位と交絡を確認し、C内比較と構成比比較を行う
H1を相対的に支える結果：C内の変化が残り、構成比だけでは説明しにくい
H2を相対的に支える結果：C内の明確な変化が乏しく、構成比差が整合する
保留にする結果：独立試料不足、測定不足、両機序が共存し区別できない
更新先：synthesis内の競合仮説・reportの適用範囲
```

この例は単純化しており、結果の一意な因果解釈や具体的な統計手法を保証しない。実際のデータに合わせて設計を確定する。探索で見つけた仮説を同じデータで確認した場合、その範囲の整合性確認として扱い、独立検証とは呼ばない。

「検証可能性が高い」を「正しい」に置き換えない。費用が低く区別しやすい仮説を先に調べることと、支持の強さは別の判断である。

## 5. 今回深追いしない部分

[レビュー著者の整理：Integrated AI systems / Discussion](https://pmc.ncbi.nlm.nih.gov/articles/PMC13674306/) 本論文は統合されたAIシステムや評価・再現性なども議論するが、レビューが紹介する個別システムの成果は本資料で原著照合していない。

[採用判断] multi-agent構成やツール一覧の導入は今回の要件にしない。今回必要なのは科学的判断を受け渡す接続であり、登場する役割の数ではない。一般的なLLM自己採点を仮説の科学的検証として採用しない。

また、論文の刊行年は2026年でも解析対象の締切は2025年7月。後続システムを含めた2026年時点の網羅的性能比較とは読まない。枠組みの有用性と、枠組みに従えば発見の質が上がるという因果的効果は区別する。
