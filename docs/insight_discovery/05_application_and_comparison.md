# 4本から何を採り、どう実行するか

[索引](00_index.md) · [既存ワークフロー](../agent_workflow/01_workflow_and_files.md)

この文書の操作・書式・例・評価案はすべて **[応用案・未検証]**。原典の標準手順ではない。元の4課題への対応を整理したうえで、既存の解析→逐次保存→全体見直し→複数図と1つのレポートという流れに接続する。

## 1. 課題別に比較すると

| 元の課題 | Foresight | Russellら | DataSite | EXHYTE |
| --- | --- | --- | --- | --- |
| 関心への集中・見逃し | 特徴の型、条件付き探索、俯瞰 | 今の表現に収まらない情報を変更の契機にする | 主たる操作とは別の候補を供給 | 探索・仮説・確認の接続漏れを点検 |
| 情報過多 | 型別の候補選択。ただし上位選択の偏り | 目的作業に合う表現を選ぶ | 短文→図→追加探索。ただし通知過多 | 優先順位付けの役割を明示。具体的UIはない |
| 結果間の横断理解 | 同じ定義で比較できる統計的関係に強い | 比較軸そのものを改める点が重要 | 異なる計算結果を提示するが意味的接続は残る | 観察・仮説・検証の接続を整理 |
| 複数解釈・条件依存 | 統計的特徴の列挙だけでは足りない | 分類・表現を変更できる。ただし仮説評価法ではない | 候補を増やせるが競合仮説の保持は別設計 | 仮説候補と検証への接続を考える枠組み |

比較の原典根拠は各詳細：[Foresight](01_foresight.md)、[Russellら](02_cost_structure.md)、[DataSite](03_datasite.md)、[EXHYTE](04_exhyte.md)。どの論文も、読者向けのMarkdownレポートの理解を直接検証したものではない。

## 2. 最小の一巡

1. **候補の型を選ぶ。** 今回の問いに対して、再現・反転・部分集団・手法間の補完など、何を探すか決める。比較可能な対象と条件を明示する。
2. **候補を探し、選別の外も見る。** まず既存の出力から拾う。一つの対象を深めたら、他の対象・手法・条件や未確認へ戻る。
3. **収まらない結果から比較軸を見直す。** 不一致を無理に平均化せず、時点・測定対象・集計単位を展開する。
4. **説明の候補と区別する確認を置く。** 予想される観察、代替説明、実行条件を記す。追加計算が必要ならコードと出力を通常の場所へ保存する。
5. **結果から主張を更新する。** 掲載するもの、例外、保留、未確認、次の確認を整理し、複数図で1つのレポートへまとめる。

全手法の全組合せを毎回実行する方式にはしない。予算・重要性に応じて範囲を決め、残りを未確認として示す。

## 3. 複数データ・複数手法の架空例

以下は説明のための架空の入力であり、実データ・実際の解析結果ではない。数値の捏造を避け、定性的な関係だけを設定する。

### 入力：保存済みの解析結果

| 結果 | 仮定する観察 | 直ちには言えないこと |
| --- | --- | --- |
| F1：scRNA-seq A、DEG | 細胞型Cで経路P関連遺伝子群が上昇方向 | Pの機能や因果機序を実証した |
| F2：A、pathway | 同じCでPの上昇方向を示唆 | F1と独立した裏付けを得た |
| F3：scRNA-seq B、pathway | CでPが逆方向を示唆 | A/Bが同条件で矛盾している |
| F4：A、CCI | CからDへのL–R相互作用候補スコアが上昇 | 実際の分泌・結合が増えた |
| F5：安全性情報 | 別組織Tで受容体Rの発現を報告 | 有害事象が生じる、またはAと同じ状態である |

A/Bでは対象・比較の向き・時点などの対応を未確認とする。F1/F2は同じ試料・発現データを使うと仮定する。

### 操作1：候補の型で拾う

Foresightの探索構造を参考に、次を別々の理由で候補化する。

- F1＋F2：手法間の整合候補。強さではなく、同じ現象への対応で拾う。
- F2＋F3：方向不一致候補。条件一致は未確認と明記する。
- F1＋F4：機序の補完候補。経路PとL–Rを接続する根拠は未確認。
- F4＋F5：安全性の追加確認候補。異なる組織・資料の接続条件は未確認。

F5は主たる解析と離れており、同じランキングでは落ちる可能性がある。DataSiteから採る「関心外の一巡」では、このような判断の制約になる結果も探す。F5だけで危険を断定せず、今回の判断に関係する条件がそろうかを確認する。

### 操作2：比較できないことを表にする

| 候補 | 先に確認すること | 現段階の処置 |
| --- | --- | --- |
| F1＋F2 | 対象遺伝子の重複、共通入力 | 整合として保持。独立証拠数を増やさない |
| F2＋F3 | 時点、比較の向き、細胞型対応、経路定義 | 不一致候補として保留 |
| F1＋F4 | PとL–Rの関係、測定対象、共有する発現情報 | 機序仮説。実測された相互作用としない |
| F4＋F5 | 種・組織・条件・発現と機能の対応 | 適用条件を確認する問いとして保持 |

### 操作3：residueから軸を変える

「AはP活性化、BはP抑制」というデータ別の結論ではF3を説明しにくい。Russellらを参考に、データ別の章から、**P×細胞型×時点×測定対象**の比較へ変える。

変更後、時点が違うと分かっても、それだけで時点差が機序だとは結論しない。「同時点の再現性は未評価」「条件が異なるので共通方向を主張できない」と整理できる。この結果も、比較軸変更の有用な成果である。

F5はP中心の表へ無理に入れず、「L–R候補を介入へ結び付ける際の適用条件」という別の問いに接続する。すべてを一つの機序へまとめることを成功条件にしない。

### 操作4：区別する確認を計画する

EXHYTEを参考に、実行可能な確認へ落とす。

| 説明候補 | 次に確認するもの | その結果から変える判断 |
| --- | --- | --- |
| Pの変化が条件依存 | A/Bの条件対応、可能なら対応条件での比較 | 一般的共通性か、限定的な傾向か |
| 細胞構成が全体の結果に寄与 | 試料ごとの構成比とC内の変化 | 全体変化と細胞内変化の区別 |
| CCI候補がPと関係 | L/R発現、経路への接続根拠、独立した測定の有無 | 記述的な整合か、機序仮説か |

入力が不足すれば、実行済みの検証にせず保留へ戻す。同じ発現データの再集計は感度・整合性の確認であり、独立実験の代わりにはならない。

### 操作5：レポートを作る

この架空例なら、次の3図が候補になる。実際の値・入力がないため、今回は作図していない。

1. Pの変化をデータ・細胞型・条件で並べる図。方向と不確実性、未測定を区別する。
2. DEG・pathway・CCIの対応と共有入力を示す図。観察、仮説的な接続、依存を区別する。
3. 競合説明と、それを区別する確認の対応表。実施済み・計画・実施不能を明示する。

本文は「Pが一貫して活性化する」とせず、共通する範囲、逆方向の候補、関係が未確認の部分を説明する。詳細には元出力と比較表へ戻るリンクを付ける。

## 4. 増やす保存層は不要

| 既存の保存先 | この調査から補う内容 |
| --- | --- |
| `analysis_history.md` | 探した条件、実際に見た範囲、実行した追加確認 |
| `findings.md` | 観察・条件・根拠。本文に入れない例外や未整理も保持 |
| `synthesis.md` | 候補の型、比較可能性、軸の変更、競合仮説、次の確認、採否 |
| `scripts/`・`results/` | 実際に実行した計算と出力。候補メモの値の正本 |
| `report.md` | 問いへの答え、複数図、主要な例外と適用条件、根拠へのリンク |

記録は候補ごとの大量の専用カードにせず、既存比較表の行や一巡のメモで始める。数値・条件・IDの二重管理を増やさない。

## 5. 試すなら、何を測るか

今回は架空例による手順の机上照合のみ。効果を確かめる次の試験では、同じ出力・モデル・予算で次を比較する。

| 比較 | 確かめたいこと |
| --- | --- |
| 通常の全体見直し vs 型を指定した候補探索 | 既知の重要関係・例外を拾えるか。誤関係や重複が増えないか |
| 比較軸を固定 vs residueを契機に変更 | 条件違いの誤統合を減らし、別解釈を保持できるか |
| 候補記録まで vs 実行可能な確認と改訂まで | 確認が実行され、主張が結果に応じて更新されるか |

専門家の既知関係一覧への回収率だけで判定せず、一覧外の正当な発見も別途評価する。候補生成量、重要関係、誤り、未確認、記録・確認の費用を分けて報告する。読者理解の評価は別に行い、根拠・条件・代替説明を正しく答えられるかを確認する。

## 6. 残る問題

どの型にも入らなかった未知の関係の検知、異質な測定をつなぐ分野知識の正しさ、選別前の元出力にある見落としは残る。多数の候補を保存することと、それらを理解・検証することも別である。

したがって、最初の導入は**一つの重要な不一致と、その周辺の出力**に限定するのが妥当である。候補探索・軸変更・確認・本文更新まで通し、効果と費用を見て対象を広げる。この導入判断も本資料の提案であり、4論文が検証した最適方針ではない。
