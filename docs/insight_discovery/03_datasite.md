## 1. 原典の仕組み

[原典の整理：Server-Side / Scheduling、PDF pp.5–7](https://www.cs.au.dk/~elm/pdf/datasite.pdf)

利用者の操作と並行して分析を実行し、結果を短い文章のフィードへ送る。詳細な図を展開し、主画面で追加探索できる。計算モジュールとschedulerを分け、入力型、計算量、関連性などを使って実行順を決める。相関、回帰、クラスタリング等が対象で、単一モジュールの失敗から他の実行を分離する。

## 2. 評価から何が言えるか

[原典の整理：Evaluation / User Studies / Discussion、PDF pp.7–12](https://www.cs.au.dk/~elm/pdf/datasite.pdf)

映画・航空機への鳥衝突のデータを、各ツール20分で探索する研究を実施。Study 1は16人、PoleStar比較で属性集合のcoverageが30%増えた。Study 2は12人、Voyager 2比較でcoverageは同程度。参考になると発話した図は後者でも増えたが、科学的な発見の正しさを示す指標ではない。効率の主観評定差もVoyager 2比較では有意でない（p=0.14）。著者らは通知過多や総当たりの限界も論じる。

## 3. Foresightとは何が違うか

[調査に基づく判断] Foresightは「特徴の空間をどんな条件で探すか」の参考になり、DataSiteは「主たる探索以外に計算を走らせ、候補をどう受け渡すか」の参考になる。どちらも自動候補を扱うが、今回必要なのは後者のUI一式ではなく、**現在の問いに関係する探索と、現在の問いから外れる探索の配分**である。

例えば、経路Pの説明を深める一巡とは別に、未確認の細胞型、反対方向の変化、別手法でだけ現れる結果を確認する一巡を置く。常時バックグラウンド実行ができなくても、この役割は実現できる。

## 4. 計算モジュールを比較操作として使う

以下は **[応用案・未検証]**。原典にある汎用分析モジュールを、生物学的解析へそのまま転用するものではない。

実装に進む前でも、各操作を次の契約で定義すると、無効な比較を避けやすい。

```text
操作：データ間の方向不一致候補を探す
入力：対応する対象・条件を持つ効果量表
実行条件：比較の向きと測定対象を対応づけられる
実行内容：同じ対象の効果方向を照合し、不一致候補を抽出
返すもの：対象、条件、両効果、元出力、比較上の制約
失敗・対象外：対象対応不明、効果量なし、条件不一致
候補を読む理由：共通性という主張の範囲を変える可能性
```

CCIのスコアとDEGのlog fold changeを相関させる操作を、列が数値であるという理由だけで実行してはいけない。両者を対応させる観測単位と意味が必要である。実行条件を満たさない場合も、失敗や比較不能を「候補なし」と区別して返す。

## 5. 候補通知は短く、採用理由へつなぐ

[応用案・未検証] 既存の`synthesis.md`に次の程度のメモを置く。すべての完了タスクを同じ重みで通知しない。

```text
候補：細胞型Cで、データA/Bの経路Pの方向が異なる
確認する理由：「共通の活性化」という主張を制限し得る
根拠：対応する2出力と条件表
まだ不明：採取時点・細胞構成の違い
次の操作：時点と細胞構成を合わせられるか確認
```

短文だけで判断できる単純な情報と、図・分布が必要な情報を分ける。複雑な候補は元図や表まで読む。自動生成文に「機序を発見した」と書かず、「どの比較を確認する価値があるか」を記す。

同じ出力を別の表現で何度も候補化した場合は、入力・対象・条件・関係の型で重複をまとめる。条件が違う結果や例外はまとめて消さない。採用、保留、比較不能、重複などの処置を既存比較表へ残す。

## 6. 追加探索の順番と停止

[応用案・未検証] 次の順序は固定アルゴリズムではなく、限られた予算での初期案である。

1. 既存の出力を読むだけで確認でき、主要な主張を変え得る候補。
2. 矛盾や未分類を理解するための比較。
3. 現在の説明と離れた領域の点検。
4. 新しい高コストの解析が必要な候補。

第4項目でも、判断を大きく変え得るなら前倒しする。費用だけを基準にすると、安いが似た結果ばかりが増える。

一巡後に、新しい候補が重複中心なのか、重要な未確認が残るのかを確認する。予算を使い切った場合は未確認を残して停止する。「これ以上重要な結果はない」と書かない。節目で止める方式と継続的探索のどちらが有効かは、実際に比較する必要がある。

## 7. 採用判断と検証方法

**採る：関心外の探索機会、入力条件のある操作、短文から詳細への受け渡し、実行不能の明示。** 専用フィード、常時実行のサーバー、無制限の解析追加は要件にしない。

[応用案・未検証] 同じ入力・モデル・計算予算で、節目の追加探索あり／なしを比較する。候補件数だけでなく、重要な例外の回収、誤った関係、重複、候補確認時間を測る。人間の探索UIでの効果が、そのままAgentの統合性能や読者理解へ移るとは扱わない。
