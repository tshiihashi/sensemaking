# The Cost Structure of Sensemaking：理解できない結果から表現を変える

[索引](00_index.md) · [既存の短い整理](../sensemaking/02_process_and_representation.md) · [適用例](05_application_and_comparison.md)

Daniel M. Russell, Mark J. Stefik, Peter Pirolli, Stuart K. Card. *The Cost Structure of Sensemaking*. INTERACT '93 / CHI '93, 誌面pp.269–276, 1993。[DOI](https://doi.org/10.1145/169059.169209) · [著者公開PDF](https://www.markstefik.com/wp-content/uploads/2014/04/1993-Cost-Structure-of-Sensemaking1.pdf)。

## 1. 何が参考になるか

[調査に基づく判断] 比較表に大量の結果を入れても意味が見えない場合、「もっと要約する」の前に、**その表現が必要な比較を可能にしているか**を見直す根拠になる。今回の4本のうち、異なる結果を横断して理解する作業の設計にもっとも深く関わる。

## 2. 原典の具体的な考え方

[原典の整理：Case Study / Learning Loops、PDF pp.1–3](https://www.markstefik.com/wp-content/uploads/2014/04/1993-Cost-Structure-of-Sensemaking1.pdf)

レーザープリンター技術者の共通教材を設計する事例を扱う。情報を入れるschema自体を変更しながら、機種間の共通点・違いを比較する。representationは表示形式だけでなく、何を項目・関係として持ち、どんな操作を行うかを含む。

表現を探すgeneration loop、情報を当てはめるdata coverage loop、表現を変更するループを区別する。既存分類に収まらない情報、必要なのに欠けている情報、使われていない表現などのresidueが変更の契機になる。分類の統合・分割・追加を行い、作った表現を課題に使う。

[原典の整理：The Cost Structure of Sensemaking、PDF p.6](https://www.markstefik.com/wp-content/uploads/2014/04/1993-Cost-Structure-of-Sensemaking1.pdf) 全体の費用を、表現の発見、情報の探索・抽出、表現への符号化、目的作業に分けて考える。構造化への投資は、その後の作業の量・質との関係で評価する。現代のLLMを比較した実証研究ではない。

記号では `C_total = C_FR + C_IE + C_FD + C_TP` と読める（FR：表現の発見、IE：符号化、FD：情報探索・抽出、TP：目的作業）。工程間を往復する際の作業も含めて費用を考えるための分解であり、各項を定数時間の一回の処理とする性能保証ではない。

## 3. 「表現を変える」を具体化する

以下は **[応用案・未検証]**。見た目の表を図へ変えるだけでは不十分な場合がある。先に、何を比較できるようにしたいかを決める。

| 現状と困り方 | 変更するもの | 変更後にできる操作 |
| --- | --- | --- |
| 手法別の章が並び、同じ現象の結果が離れる | 主な軸を「手法」から「現象・問い」へ変える | DEG・pathway・CCIの寄与と不足を一か所で比較 |
| データA/Bの結論が違うように見える | 時点・細胞型・比較の向き・測定対象を明示 | 真の不一致候補と条件違いを分ける |
| 全体平均では一致、部分集団で反転する | 集計単位を全体から部分集団へ掘り下げる | 共通効果と条件依存の候補を比較 |
| 一つの説明の下に例外が増える | 結論の分類から競合仮説×予測へ変える | どの出力が仮説を区別するか確認 |
| 「独立した裏付け」が多数に見える | 手法別一覧に入力・特徴量・参照DBの共有を加える | 一致と証拠の独立性を分ける |

ここで、整理の単位を変えても元結果の測定対象は変わらない。例えば、発現に基づくCCI推定を「実際の分泌」へ書き換えるのは表現変更ではなく、根拠のない主張の追加になる。

## 4. residueを次の操作へ変える

[応用案・未検証] 未分類メモをためるだけでなく、「なぜ今の表に置けないか」を一文で記す。

```text
扱えない結果：データBでは同じ経路Pの方向が逆
今の表現の問題：データ別の結論しかなく、時点が隠れている
変更候補：経路P × 時点 × 細胞型で比較し直す
必要な追加情報：両データの採取時点と比較の基準
変更後の確認：不一致が残るか、新たな例外を隠していないか
```

この段階で「時点差が原因」とは決めない。表を変えた結果、比較可能になったのか、それとも比較不能と分かったのかを記す。

residueには複数の処置があり得る。

- **欄が足りない**：測定対象や時点など、必要な属性を追加する。
- **区分が粗い**：群を分割する。ただし細分化で推定が不安定になる場合は保留する。
- **同じものを別名で扱っている**：対応表で統合する。対応が曖昧なら別々に保持する。
- **観察と説明が混ざる**：事実の行と、仮説・前提の行を分ける。
- **必要な結果がない**：未測定・出力未確認を明記し、追加解析か主張の制限を選ぶ。

どの変更も可能性を増やすだけでは足りない。**変更前にできなかった比較が何か、変更後にそれができたか**を短く確認する。

## 5. 保存・整理にかかる費用も評価する

[応用案・未検証] 全結果を完全なカードへ変換する前に、代表的な不一致を一つ選び、必要な列だけで比較を試す。効果がなければ全件へ展開しない。

| 費用 | 今回観察するもの |
| --- | --- |
| 表現を考える | 比較軸の案出・変更にかかる時間 |
| 元情報へ戻る | 出力・条件・該当箇所を探す時間 |
| 記録する | 抽出、転記、用語対応、リンク修正の時間 |
| 比較・報告する | 関係の判断、根拠照合、本文編集の時間 |

検索時間が減っても、転記・更新・再確認が増えれば全体として改善しない場合がある。反対に時間が増えても、重要な例外や誤統合を見つけられるなら採用する理由になり得る。時間と発見・誤りを別々に報告する。

記録先は既存の`synthesis.md`でよい。変更した比較軸と理由を短く残し、数値の正本は`results/`へ戻れるようにする。すべての中間表を永続保存する義務は設けない。

## 6. 採用判断と限界

**採る：分類不能を保持する、必要な比較に合わせて表現を改める、整理費用を全工程で評価する。** とくに複数解釈を一つへ押し込まない設計に役立つ。

この研究だけでは、いつ表現を変えるべきかの閾値、最適な図形式、LLMにとって最良のスキーマは決まらない。Agentが分類を変えた回数を、そのまま人間の理解の深化とみなすこともできない。分類を頻繁に変えると追跡・更新費用が増すため、小さな試行で比較操作の改善を確かめる。
