# 5. Agentによる解析レポート作成スキルへの設計案

## 1. このファイルの位置付け

**本ファイルは論文の要約ではなく、論文と既存の課題整理を基にした応用案である。** フィールド、手順、判断表、評価方法は本資料で追加した。論文がAgentに対してこれらを検証したわけではない。

主な着想源は、知見保管庫を含む循環モデル（p.3、pp.23–24）、ドメイン情報（pp.8–9、25–26）、グラフ・階層と来歴（pp.17–19）、ファクト集合の冗長性と例外（p.20）、top-down検証（p.26）、偽発見・バイアス（pp.12–13、27）である。

## 2. スキルが達成すべきこと

多数の解析結果から、読者の問いに必要な知見を示す。同時に、結果の関係、複数の妥当な解釈、重要な例外・反証、適用条件を追跡可能に残す。

対象は、解析済みの結果からレポートを作る場合と、レポートの不足を埋めるため追加解析を行う場合である。業務上の意思決定・公開・配信を、レポート生成の指示だけから追加で実行するものにはしない。

## 3. 既存の4課題との対応

| 既存の課題 | 設計の対応 | 注意点 |
|---|---|---|
| 特定現象に集中して他を見逃す | 探索範囲と未確認範囲の記録、予想外の結果・反証・例外の台帳 | 「全パターンを網羅した」とは主張しない |
| 網羅しようとすると情報過多 | 保管庫と本文を分離し、要約→主要論点→詳細の階層にする | 判断を変える限定条件まで付録へ追いやらない |
| 結果が分散し全体像が見えない | 共通IDと対象条件、関係表、論点別の横断整理 | 似た文章だけで重複・矛盾を判定しない |
| 解釈・最適結論が一意に決まらない | 仮説と観測を分け、支持・反対・識別条件を併記 | 根拠の強さが違う説を同等に扱わない |

## 4. 成果物を3層で扱う

### 4.1 Evidence：計算と出典

元データの識別・版、解析コード、パラメータ、表、図、実行結果など。主張を検証できる入口を用意する。巨大なデータをMarkdownへ複製する必要はなく、アクセス可能な参照でよい。

### 4.2 Insight repository：知見・解釈・関係

観測、仮説、文脈情報、反証、保留結果を構造化する。知見に安定したIDを付け、どの証拠を使ったか、どの知見と関係するかを記録する。

### 4.3 Reader view：読者向けレポート

読者の問いに沿って知見を編集する。本文の短さと、保管庫の情報量は別に調整する。本文から根拠や別解釈へ到達できるようにする。

3層は必ず3ファイルに分けるという意味ではない。小規模なら一つのMarkdown内の区画とリンクでもよい。

## 5. 推奨する作業手順

### Step 1：目的と利用条件を確認する

最低限、次を特定する。

- 誰が読むか、何を理解・判断するためか。
- 対象データ、期間、分析単位、主要指標の定義。
- 探索レポートか、事前仮説の確認か、意思決定の比較か。
- 納品形式と利用可能な解析成果物。

不足情報をすべて質問するのではなく、読み取れるものは既存資料から補う。判断に影響する未確認事項は仮定として明示し、必要な情報だけ確認する。

### Step 2：既存成果物と探索範囲を棚卸しする

解析結果、図表、ノート、コード、過去レポートを確認し、探索軸の表を作る。

| 観点 | 記録例 |
|---|---|
| 対象・集団 | 全体、地域、商品、顧客群 |
| 時間 | 長期推移、前年同月、イベント前後 |
| 指標 | 水準、増減、比率、件数、ばらつき |
| パターン | 共通傾向、差、外れ値、例外、関係 |
| 状態 | 確認済み／未確認／対象外と、その理由 |

これは全組み合わせを総当たりする義務ではない。目的と計算量に応じて選び、未確認範囲を可視化するための表である。

### Step 3：レポートを書く前に候補知見を記録する

意味のある結果を得たら、知見カードにする。

1. 何が観測されたか。
2. 対象、比較条件、集計、値・単位。
3. 根拠となる表・図・コード。
4. なぜ重要か、どの問いと関係するか。
5. 制約、不確実性、検証状態。
6. 仮説や文脈情報へのリンク。

ほぼ同じ結果を大量に別カードへ増やさず、同一現象の反復はまとめる。ただし、条件や方向が異なる例外を消さない。

### Step 4：品質と意味を検証する

確認を分ける。

| 確認 | 主な問い |
|---|---|
| データ・計算 | 欠損、単位、母数、集計粒度、期間は適切か。再実行できるか |
| 探索・統計 | 多数の候補から選んだ影響はあるか。検定・検証の前提に合うか |
| ドメイン | 指標定義、業務イベント、既知の仕組みと整合するか |
| 表現 | 図と文章で対象・方向・値が一致するか |

すべてに同じ検定や外部調査を強制しない。重要な主張に必要な強さの検証を行い、できなかったものは明記する。

### Step 5：複数結果を横断して関係を整理する

候補の対を、支持、補完、重複、例外、矛盾、前提、比較不能などで整理する。これらは本資料の提案した関係名である。

矛盾に見える場合は、対象、期間、単位、分母、集計方法、データ版を先に揃える。全体と部分集団で方向が違う場合、単純な誤りとも、一方を削除すべき重複とも限らない。

同じデータの別グラフから同じ結果を得た場合は、表現の一致としては有用でも、独立した検証データが増えたとは扱わない。

### Step 6：解釈を比較する

説明が複数成り立つなら、仮説ごとに次を並べる。

- 支持する観測。
- 反対する観測・説明できない例外。
- 必要な前提や未確認の文脈。
- その説明が正しい場合に期待される追加観測。
- 仮説を区別する追加解析やデータ。

代替仮説を形式的に同数作る必要はない。実質的に成立するものを挙げ、根拠の差を示す。

### Step 7：本文の知見を選ぶ

「珍しい」「スコアが高い」だけで選ばず、集合としてバランスを確認する。

| 基準 | 掲載判断への使い方 |
|---|---|
| 問いへの関連 | 読者の問いに直接答えるか |
| 判断への影響 | 結論や次の行動が変わるか |
| 根拠の強さ | 記述事実か、追加検証済みか、推測か |
| 適用範囲 | 全体か、一部だけか。条件依存か |
| 補完性 | 既存の本文にない重要な側面を足すか |
| 反証・例外 | 主結論を限定・修正するものか |
| 冗長性 | 同じ内容を繰り返していないか |
| 読者の負担 | 説明量に対して得られる理解があるか |

各項目を機械的に加算した標準点数は定めない。利用目的により重要度が異なるからである。根拠が弱くても判断に重大な影響があり得るものは、「重要だが未確認」として本文に残す場合がある。

### Step 8：階層的にレポートを構成する

- **入口の要約：** 主な発見、判断の条件、主要な不確実性。
- **論点別の本文：** 観測→根拠→意味→代替解釈・制約。
- **横断整理：** 複数結果の一致・例外・矛盾、結論が変わる条件。
- **詳細：** 方法、追加図表、候補一覧、未確認事項、知見・証拠へのリンク。

固定の見出し数やページ数を強制しない。本文を読んだだけで過度に確実な結論に見えるなら、重要な限定条件を本文へ戻す。

### Step 9：草稿から解析へ戻る

「原因は何か」「どの集団でも成立するか」「なぜ二つの図が違うか」といった疑問を、追加解析の問いとして取り出す。重要度、解析可能性、必要コストで優先する。

進められる追加確認を行い、知見カード・関係表・本文を更新する。必要データがない場合は推測で埋めず、判断不能な点と追加情報を示す。

### Step 10：最終確認と引き継ぎ

本文の主要主張から根拠へ戻れるか、条件・例外・別解釈が保持されるかを確認する。未解決事項には、次に調べる問い、必要な資料、現時点で判断できない理由を付ける。

## 6. 状態の扱いと停止条件

知見の「検証状態」と「掲載状態」を分ける。検証済みでも本文に不要なもの、未検証でも重要な注意事項はあり得る。

- 検証状態の例：観測済み、計算確認済み、追加検証済み、未検証、棄却、判断不能。
- 掲載状態の例：本文、詳細資料、保留、対象外。

「追加検証済み」は何を検証したかを必ず添える。検定、別集団、別期間、独立データ、専門家確認は同じではない。一般的な一つの確信度スコアにまとめる必要はない。

次を満たしたら、目的に対するレポートを完成とする。

1. 主要な問いに、結果または判断不能の理由が対応する。
2. 主要主張は出典・対象条件に戻れる。
3. 判断を変え得る既知の反証や制約が扱われている。
4. 残った重要な不確実性と未確認範囲が示されている。
5. 追加解析を終える理由が、目的・データ・費用に照らして説明できる。

「すべての知見を見つけた」ことを停止条件にすると終わらないため、既知の探索範囲と未確認範囲を明示して止める。

## 7. 後でスキル化するときの分割案

今回のMarkdownは参照資料である。実際のスキルは、すべてを一括で読み込ませるのではなく、必要な部分を参照する形がよい。

```text
analysis-reporting/
  SKILL.md
  references/
    insight-records.md
    synthesis-and-alternatives.md
    report-structure.md
    review-criteria.md
```

| 配置 | 載せる内容 | この資料から抽出する部分 |
|---|---|---|
| SKILL.md | 使う場面、成果物、必須の区別、短い作業フロー、参照条件 | 本ファイル§2–6の要点 |
| insight-records.md | 知見、根拠、文脈、状態の記録方式 | 06の知見・来歴テンプレート |
| synthesis-and-alternatives.md | 重複・例外・矛盾、仮説比較 | 本ファイルStep 5–6、06の関係表 |
| report-structure.md | 読者別の構成、本文と詳細の選択 | 本ファイルStep 7–8、06の雛形 |
| review-criteria.md | 検証項目、完了条件、評価ケース | 本ファイル§6、8、06のチェック |

これは候補構成であり、最初から全ファイルを作る必要はない。短いスキルで十分ならまとめる。原典の研究史や全システム一覧は背景資料として保持し、毎回の指示にはコピーしない。実行コードは、反復利用する処理が明確になってから追加する。

## 8. スキルを評価するためのケース

| ケース | 期待する観察可能な振る舞い |
|---|---|
| 同一結果を複数の図で示した入力 | 重複を減らし、元の参照を残す。独立証拠として水増ししない |
| 全体傾向と一部集団が逆方向 | 両方を保持し、集計条件と例外の意味を説明する |
| 一つの観測に複数の説明 | 観測と仮説を分け、識別する追加情報を示す |
| 目立つ外れ値と弱い検証 | 注目度と確実性を区別し、断定を抑える |
| 関心外だが重大な結果 | 保管し、読者の判断に関係する場合は本文で扱う |
| 文脈情報がない入力 | 原因を創作せず、記述と未確認解釈を分ける |
| 短い要約の指定 | 要約を短くしても、結論を変える制約・反証を残す |
| 異なるデータ版の結果 | 版の違いを確認し、単純な矛盾として処理しない |
| 根拠のない流暢な草稿 | 根拠の欠落を検出し、弱める・検証する・削除する |

評価は見出しの一致ではなく、主張の正確性、重要な例外の保持、根拠への到達性、複数解釈の扱い、読者が判断条件を説明できるかで行う。比較実験をする場合は、同じ入力を使い、通常の要約とスキル適用後を比較する。合否の閾値は実際の用途に合わせて定める。
