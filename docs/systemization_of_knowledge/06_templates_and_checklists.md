# 6. スキル化に向けたテンプレートとチェック項目

**以下は本資料が提案する運用テンプレートであり、論文に掲載された標準様式ではない。** 小規模な解析では項目を減らしてよい。空欄を推測で埋めず、「未確認」「該当なし」を理由とともに書く。

## 1. 成果物の最小構成

```text
analysis-output/
  report.md                 # 読者向けの本文
  insights.md               # 知見・仮説・関係の記録
  evidence/                 # 既存の表・図・実行結果等。必要な場合だけ設置
```

大きな解析では、知見を個別ファイルに分け、索引、探索範囲、関係表を分離できる。既存のNotebookや解析成果物があるなら、複製せず参照する。

## 2. 解析・レポートの前提メモ

```markdown
# 解析・レポートの前提

- 目的・問い：
- 想定読者と利用場面：
- レポートの性格：探索／仮説確認／判断比較／その他
- 対象データと版：
- 対象期間：
- 分析単位・母集団：
- 主要指標と定義：
- 既存の分析成果物：
- 確認済みのドメイン情報と出典：
- 置いた仮定：
- 対象外・未確認の範囲：
- 完了条件：
```

## 3. 探索範囲の台帳

```markdown
| 問い・観点 | 対象条件 | 確認した分析 | 関連知見ID | 状態 | 未確認・対象外の理由 |
|---|---|---|---|---|---|
| ... | ... | ... | I-... | 確認済み／未確認／対象外 | ... |
```

この台帳は「解析空間をすべて網羅した」という証明ではなく、実際に見た範囲を示す。検討した候補・実行した比較が統計解釈に影響する場合は、その記録も保持する。

## 4. 知見カード

```markdown
## I-<ID>：<短い見出し>

### 観測されたこと

<データから直接言える内容。解釈や原因は分離する。>

### 対象と計算条件

- データ・版：
- 期間・対象・除外条件：
- 分析単位：
- 指標・単位・分母：
- 集計・比較・変換：
- 値、効果の大きさ、利用可能な不確実性の情報：

### 根拠

- 表・実行結果：
- 図と、該当する箇所：
- コード・Notebook・パラメータ：
- 再現に必要な条件：

### 意味と関連性

- 関連する問い：
- 重要である理由：
- 確認済みの文脈：
- 解釈候補ID：
- 適用範囲・例外：

### 品質と状態

- 検証状態と、実施した確認：
- 不確実性・制約：
- 探索から選ばれたことの影響：
- 掲載状態：本文／詳細／保留／対象外
- 掲載・保留の理由：
- 関連知見と関係：
- 作成者・更新時点：
- 次に確認すること：
```

### 4.1 入力負担を下げる最小カード

```markdown
## I-<ID>：<観測>

- 対象・期間・集計：
- 根拠：
- 意味・関連する問い：
- 未確認の解釈・制約：
- 関連知見：
- 検証状態／掲載状態と理由：
```

ファクトの数値は可能なら実行結果を参照し、本文・カード・表で独立に再入力して不一致を増やさない。

## 5. 文脈情報の記録

```markdown
## C-<ID>：<指標定義・業務イベント・専門知識など>

- 内容：
- 出典・確認者：
- 情報の対象期間・有効範囲：
- 確認状態：確認済み／仮定／未確認
- 関連するデータ・知見：
- 解釈へ与える影響：
- 制約・反対情報：
```

文脈情報が存在することと、それが観測結果の原因であることは分ける。たとえば、施策開始日が確認できても、施策の因果効果が確認できたとは限らない。

## 6. 仮説・代替解釈の比較

```markdown
## H-<ID>：<説明候補>

- 説明しようとする観測ID：
- 仮説の内容：
- 必要な前提・文脈ID：
- 支持する証拠：
- 反対する証拠・説明できない例外：
- 代替仮説ID：
- 正しい場合に期待される追加観測：
- 否定・限定する追加観測：
- 識別に必要なデータ・解析：
- 現時点の判断と理由：
```

```markdown
| 仮説 | 説明できる結果 | 反証・弱点 | 必要な前提 | 区別する追加確認 | 現時点の判断 |
|---|---|---|---|---|---|
| H-... | I-... | I-... | C-... | ... | ... |
```

根拠の薄い説明を、十分支持された説明と同等に並べない。判断を保留する場合は、単に「可能性がある」で終えず、何が不足しているかを示す。

## 7. 知見間の関係表

```markdown
| 関係ID | 始点 | 関係 | 終点 | 成立する条件 | 根拠・補足 |
|---|---|---|---|---|---|
| R-... | I-... | 支持／補完／重複／例外／矛盾／前提／比較不能 | I-...またはH-... | ... | ... |
```

| 関係 | 判定の目安 | 注意 |
|---|---|---|
| 支持 | ある仮説・主張と整合する証拠 | 整合するだけで仮説を証明したとはしない |
| 補完 | 異なる側面から同じ論点を説明する | 同じデータ由来なら独立性に注意 |
| 重複 | 同じ対象・条件・意味をほぼ繰り返す | 対象や適用範囲が違う場合は統合しすぎない |
| 例外 | 共通傾向が成り立たない対象・条件 | 件数が少なくても判断を変える場合がある |
| 矛盾 | 条件が整合するのに両立しない | データ版、単位、母数、集計、期間を先に確認 |
| 前提 | 解釈の成立に必要な条件 | 未確認の前提を事実として使わない |
| 比較不能 | 対象や定義の違いにより直接比較できない | 無理に一致・矛盾へ割り当てない |

すべての知見の全組み合わせへ関係を付ける必要はない。主要な論点や判断に関係する組を優先する。

## 8. 分析来歴の記録

```markdown
| 実行ID | 入力と版 | 操作・変換 | パラメータ・対象条件 | 出力参照 | 関連知見ID | 確認結果 |
|---|---|---|---|---|---|---|
| A-... | ... | ... | ... | ... | I-... | ... |
```

ここで残すのは、実行内容・出力・外部に説明可能な判断である。内部思考の逐語記録を保存するための様式ではない。

再現性のために必要であれば、使用環境、乱数シード、ライブラリ版も残す。単純集計などで不要な情報を一律に要求しない。

## 9. レポート雛形

以下は一例。短いレポートでは統合してよい。

```markdown
# <読者の問いに対応するタイトル>

## 要点

<主要な発見と、それが意味すること。結論を変え得る条件と
主要な不確実性を、この段階で示す。>

## 対象と方法

<データ・期間・分析単位・指標定義・主要な方法。
詳細な方法へのリンク。>

## <論点1>

### 観測

<何が起きたか。対象条件、値、比較対象を明示する。>

### 根拠

<図表、キャプション、知見ID・出力への参照。>

### 解釈と条件

<確認済みの文脈、支持される説明、代替解釈、適用範囲。>

## <論点2など>

<必要に応じて同様に構成する。>

## 結果を横断して分かること

<一致、補完、例外、矛盾をまとめる。
どの条件で結論が変わるかを示す。>

## 未確定の点と次の確認

<現時点で分からないこと、理由、優先すべき追加解析。>

## 詳細資料

- 知見索引：
- 探索範囲と未確認範囲：
- 追加図表・方法・コード：
- 主要な代替解釈・保留結果：
```

要約しか読まない読者が、主結論の確実性を誤解しないか確認する。「付録には書いてある」だけでは重要な制約の伝達として不十分な場合がある。

## 10. 図表キャプション

```markdown
図<番号>：<この図で分かること>

- 対象・期間：
- 指標・単位・集計：
- 比較対象：
- 注目箇所と関連する知見ID：
- 誤差・不確実性・注意点：
- データ／生成コード：
```

キャプションに全項目を毎回書く必要はないが、読者が図を独立に読むために必要な情報は欠かさない。軸・凡例で分かる内容を重複させるより、比較条件や重要な限定を補う。

## 11. 最終レビュー

### 11.1 主張と根拠

- [ ] 主要主張から、表・図・実行結果へ戻れる。
- [ ] 記述事実、領域解釈、仮説、推奨行動が区別されている。
- [ ] 数値、方向、対象、期間、単位、分母が本文と図表で一致している。
- [ ] 計算確認と、仮説の独立検証を混同していない。
- [ ] 同じデータの反復を独立した支持証拠として数えていない。

### 11.2 横断整理と複数解釈

- [ ] 共通傾向だけでなく、重要な例外や反証を確認した。
- [ ] 重複は整理し、元の参照と条件の差は残した。
- [ ] 矛盾に見える結果の定義・集計・対象・版を照合した。
- [ ] 実質的な代替解釈がある場合、支持・反対と識別条件を示した。
- [ ] 追加解析が当初の説明を補強する方向だけに偏っていない。

### 11.3 不確実性とドメイン情報

- [ ] 探索的に選んだ発見の解釈に、選択・多重比較の影響を考慮した。
- [ ] 不確実性の情報がない場合、検証済みのように表現していない。
- [ ] 文脈情報の出典、対象時点、確認状態が分かる。
- [ ] 原因や業務事情を、文章を完成させるために創作していない。
- [ ] 未確認範囲と、判断できない理由が分かる。

### 11.4 読者の理解

- [ ] 要約だけでも主要な条件・不確実性を理解できる。
- [ ] 専門家に自明な図の読み方を、必要に応じて説明した。
- [ ] 主要な結果間の関係が、単なる列挙に埋もれていない。
- [ ] 図の軸・凡例・尺度・色・強調が主張を誤誘導しない。
- [ ] 詳細・未採用結果へ到達できる。

### 11.5 完了・引き継ぎ

- [ ] 読者の主要な問いに、回答または判断不能の理由がある。
- [ ] 次の担当者がデータ条件と根拠を復元できる。
- [ ] 残る重要課題と追加情報を記録した。
- [ ] 目的に照らした完了条件を満たす。

チェック数の多さを品質スコアにしない。該当しない項目は省略できる。主要主張の根拠欠落や重大な反証の欠落は、他の多数の項目に合格しても相殺されない。

## 12. 架空例：観測と説明を混ぜない記録

次は様式を説明するための**架空例**であり、PDFや実データから得た解析結果ではない。

### 知見I-001

- 観測：全体売上は前四半期比で増加した。
- 条件：同一定義の売上、同じ通貨単位、四半期集計。
- 根拠：実案件では集計表・生成コードをここへリンクする。
- 制約：季節性、価格、顧客構成は未分解。
- 検証状態：説明用の架空結果。実データの確認なし。

### 知見I-002

- 観測：一部の地域では売上が減少した。
- 関係：I-001に対する地域別の例外。全体集計とは論理的に両立する。
- 意味：「すべての地域で成長」とは言えない。

### 仮説H-001

- 内容：販促施策が全体売上の増加に寄与した。
- 必要な文脈：実施時期、対象地域、内容、同時期の他の変化。
- 未確認：季節性や価格変化でも説明できる。
- 次の確認：対象・非対象の比較、時期、他要因、識別可能な分析設計。

### 本文への編集例

> 全体売上は増加した一方、一部地域では減少しており、成長は一様ではない。販促施策の寄与は解釈候補だが、季節性や価格変化を分けて確認しておらず、現時点で原因は特定できない。

このように、短い文章でも全体傾向・例外・未確定の説明を残せる。実案件では、値と根拠の参照を追加する。
