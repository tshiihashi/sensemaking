# 4. 将来方向・未解決課題・適用上の限界

## 1. ドメイン情報を知見生成に組み込む

[原典の整理：§6.1–6.1.1、pp.25–26、Figure 15(1)]

ドメイン情報は、解析後に説明を足すためだけでなく、探索そのものを方向付けるためにも重要である。領域知識は構造的・原理的で、ときに暗黙的であり、専門家が自然に行っている判断を単純な文章入力で取り出せるとは限らない。

論文は、専門家の暗黙のデータ誤りを引き出すテンプレート[93]や、個人的な知識を外在化して議論を促す設計[82,88]を紹介する。専門家と密に協働し、知識をどう使うかまで設計することが必要となる。研究データの公開は、再分析、研究間比較、多様なデータによるモデル構築にも役立つ。

### 1.1 ストーリーの文脈

自動採掘は効率的だが、文脈を欠く物語は読者への影響が弱い。Erato[128]での指摘を踏まえ、Web情報やLLMの知識、人間の創造性・直観・専門知識を組み合わせる可能性を論じる。ただし、LLMには幻覚や常識の欠如などの制約があり、有効な組み込み方は未解決である。

読者側の文脈も重要である。固定的な一本の筋書きに限らず、InsideInsights[92]のように抽象度・詳細度を選べる階層的なレポートが方向性として挙げられる。

[応用案]

- データ辞書、指標定義、業務上の出来事、既存仮説、意思決定基準を、取得元とともに記録する。
- 外部情報を使うときは、対象、時点、情報源の適合を確認する。LLMが思い出した説明を確認済みの事実にしない。
- 文脈が足りなければ、観測結果と複数の解釈候補を分けて示す。説明を完成させるために事情を創作しない。
- 読者が必要とする要約から、根拠や例外へ掘り下げられる構成にする。

## 2. Top-downの仮説駆動探索を支援する

[原典の整理：§6.2、p.26、Figure 15(2)]

探索は明示的な目的や仮説に導かれる場合があり、それでも予想外の知見が生まれる。データを見る前に期待を表明させる研究[33]などがある一方、レポートから探索へ戻る過程は技術研究で十分に重視されていない。

論文は、目的に導かれずに探索から生まれた知見を、別データでの検証を要する仮説として扱う必要を述べる。ドメインに照らした証拠収集・検証を促し、LLMがWebから支持・反対の証拠を探す可能性も挙げる。

[応用案]

草稿の主張について、支持する結果と否定・限定する結果を照合する。追加解析の問いを、「この説明を補強するには」だけでなく、「どの結果ならこの説明を撤回するか」からも作る。

なお、独立データによる検証は常に可能とは限らない。元データで直接計算できる記述統計と、そこから一般化した仮説を区別する。記述統計まで一律に未確定と扱う必要はないが、探索で選んだ規則性の一般化には選択の影響が残る。

## 3. ノート以外の外在化を広げる

[原典の整理：§6.3、pp.26–27、Figure 15(3a)]

研究の多くは発話、ペン、キーボード、テンプレートなどの文字中心の方法を使ってきた。LLMによって、コード、構造化データ、非構造化文章の処理も容易になり、検索期間後には文章とデータのリンク、視覚的証拠付きの知見抽出、主題別整理などの研究[32,52,137]が現れている。

一方、暗黙知は専門家の行動に現れることがある。操作経路や視線から、比較や注目範囲の絞り込みを捉え、知識共有へ使う可能性がある。生理信号によるひらめき・困惑の推定も将来課題として挙げる。

原文は学習スタイルに応じた代替モダリティの可能性にも触れるが、本資料では固定的な学習者類型に合わせれば成果が向上するという運用規則へ一般化しない。

[応用案]

初期のAgentスキルでは、生理信号などを新規実装する必要はない。実行済みコード、比較表、選択範囲、注釈図、データ変換、採用・保留の理由といった、利用可能で検証可能な成果物を知見の記録に含める。

## 4. 知見発見の認知効率と質を高める

[原典の整理：§6.4、p.27、Figure 15(3b)]

### 4.1 統計的な裏付け

人は図から得たパターンの統計的妥当性を十分把握せず、偽の発見を真と捉えることがある。機械の統計処理能力を使い、多重比較への対応、within-view／between-viewの検定[111]、別データによる確認を支援する方向がある。

### 4.2 認知バイアス

ヒューリスティックは意思決定を速める一方、偏りを生む。知識の呪いなどに加え、多くの認知バイアスは可視化に与える影響が十分に研究されていない。偏りの種類を理解し、どの支援が有効か検証する必要がある。

### 4.3 個人差

経験への開放性やlocus of controlなどの個人差が知見数に影響する報告がある。評価実験ではその影響を考慮し、将来的には適応的な設計へつなげる方向がある。

[応用案]

「レポートが長いほど良い」「知見が多いほど良い」という単一指標を避ける。誤った結論、重要な反証の欠落、読者が根拠に戻れないことを、文章量とは別に評価する。統計手法の選択はデータ構造・探索設計・依存関係に応じて行い、スキルに一つの補正法を固定しない。

## 5. 協調・代替モダリティ・身体性へ広げる

[原典の整理：§6.5、pp.27–28、Figure 15(D)]

実務では、異なる専門性を持つ複数人が、多様な装置・ツールで分析する。将来の自分への引き継ぎも協働として捉えられる。装置間で知見を移すこと、私的／共有の空間、途中経過の共有、来歴の保持が必要となる。

- **Immersive analytics：** XRなどの空間配置、触覚・実物操作を通じた注釈・伝達。時間と誤りだけでなく、知見生成過程の評価が課題。
- **Data physicality：** 視覚に加えて触覚、味覚、嗅覚、聴覚などでデータを経験する。分析的な発見だけでなく、好奇心や気付きなどの非分析的な知見を促す可能性。
- ISMAR、TEIで同じ検索基準を用いたところ該当がなかったと報告する。ただし、該当領域に関連研究が存在しないという証明ではなく、検索語・採否基準の影響も考慮する。

[応用案]

複数Agentや人間との引き継ぎでは、誰が何を調べ、どの条件で何を保留したかを残す。同じデータで同じ結果が出たことを、独立した裏付けの増加と数えない。共同作業のために、データ版・指標定義・知見IDを共有する。

## 6. この論文が提供するもの・未提供のもの

| 項目 | 論文で得られること | 別途必要なこと |
|---|---|---|
| 知見の概念 | データとドメイン、発見と理解を区別する整理 | 対象業務での知見の判定基準 |
| プロセス | A・B・CとDの循環モデル | 実行順序、停止条件、エラー処理 |
| 知見の保存 | data-aware、来歴、グラフ・階層などの方向性 | 具体的なスキーマ・ID・ファイル構成 |
| 統計的妥当性 | 偽発見と多重比較の重要性 | 個別解析に適した統計設計・検証 |
| 自動ストーリー | 採掘・推薦・編集手法の体系化 | Agent実装と性能評価 |
| 行動可能性 | 文脈・ドメイン知識の必要性 | 専門的判断、介入可能性、費用・影響の評価 |
| 読者向け構成 | 図と文章の接続、階層化の事例 | 対象読者に合った構成と利用テスト |

## 7. レビュー自体の制約

[原典の整理：§3.3、p.7、および方法に基づく適用範囲の整理]

1. **検索範囲の制約：** 主要17会場に限定しており、全分野・全言語・実務ノウハウの網羅ではない。
2. **検索語・採否の主観性：** 起点論文や検索語の組み立てにより集合が変わり得る。
3. **分類の主観性：** 基準の改善と複数コーダーの確認を行ったが、全件を独立した複数名で最終分類したわけではない。
4. **研究条件の偏り：** 単一利用者・デスクトップの研究が多い。
5. **レビューと性能保証の違い：** 本論文はメタ分析で共通効果量を推定したものではなく、紹介する個別結果を一つの普遍的な精度・効果に合算できない。
6. **時点の制約：** 検索期間と刊行時点には隔たりがある。現行のAgentやLLMの能力・推奨構成を保証しない。

## 8. まとめとして残す設計上の問い

[応用案]

- この結果は、データ上の事実か、領域に関する説明か、行動提案か。
- その説明を支える文脈は、確認された情報か仮定か。
- どの結果が出れば、解釈や判断を変えるか。
- 読みやすさのために省いた結果は、どこに残るか。
- 次の人・Agentが、対象条件と根拠を復元できるか。
