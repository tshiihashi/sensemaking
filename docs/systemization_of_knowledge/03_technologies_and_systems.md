# 3. 技術研究：知見の記録から自動レポート生成まで

原典§4.3（pp.13–23）の9トピックを整理する。以下のシステム説明はすべてSoKでの紹介に基づき、現行製品の機能や個別原著の実装を独立に確認したものではない。`[番号]` は原典内参考文献番号。

## 1. 知見生成のための視覚表現

[原典の整理：§4.3.1、pp.13–15、Figure 8]

### PolyCube[139]

多次元データを、重ね合わせ、並置、3Dキューブ、スライドショー等で関連付け、全体を統合して理解するsynoptic insightを支援する。紹介された質的研究では、3D表現がcoordinated viewsより有利な点が示された。これは特定の用途・条件での結果であり、3Dを一般的に推奨する根拠ではない。

### Opportunity Map[153]

データ属性がクラスにどう関係するかのルールを表のセルに配置し、ルールの強さを示す。「重要／重要でないクラス」と「操作可能／操作できない属性」という利用者指定の軸により、行動可能性を分ける。

ファクトが興味深いことと、対象に介入できることの違いを表現する事例である。

### 画面間での知見の保持[66]

デスクトップからスマートフォンへ図を変換する際、identification、comparison、trendを保持する指標を提案する。専門家が順位を付けた小画面可視化で学習した手法は、順位付けで84%の精度と紹介される。知見内容の正確性が84%という意味ではない。

[応用案]

図の種類だけでなく、「この図で何を比較・特定・理解するか」を保存する。短い要約や小さな画面に変換しても、その目的が失われないか確認する。

## 2. 知見外在化の仕組み

[原典の整理：§4.3.2、pp.15–16、Figure 9]

| 技術・研究 | 仕組み | 保存される価値 |
|---|---|---|
| ChartAccent[105] | 報道で使われた106枚の注釈付き図を調べ、形式・対象の設計空間を整理。文章、形状、強調、画像によるデータ駆動注釈 | 注釈を対象データと結び付ける |
| ActiveInk[106] | ペン・タッチで探索と記録を行き来。描く前に意味を指定するprefixと、後で指定するpostfixを比較 | 連続操作と自由な記録の適合を考える |
| Elias & Bezerianos[41] | 複数のデータ対象に紐付くcontext-aware annotation。寿命・有効性を設定し属性で検索 | 注釈の適用条件・有効範囲を残す |
| Click2Annotate[25] / Touch2Annotate[26] | 選択したデータと知見型に応じ、属性や文章の雛形を提示 | 記録の負担を下げる |

ActiveInkでは、prefixは複数の強調など素早い連続操作に、postfixは注釈やノートに適していた。操作方式に一つの正解を設けるより、記録の場面に合わせる設計が示される。

**Data-aware insight**は文章をデータに接続し、同じデータの別の図からも知見に到達できる考え方である。単にスクリーンショットに文章を付ける以上に、対象の同一性を保持する。

[応用案]

Agentの知見カードには、図のパスだけでなく、データの版、フィルタ、集計、対象属性を付ける。データ更新時に古い知見の適用を見直せるようにする。

## 3. 知見の管理・探索・推薦

[原典の整理：§4.3.3、p.16]

ノート・注釈の著者、時刻、関連データ属性といったメタデータが、管理や推薦に使われる。

- **FacetNotes[7]：** 図上の注釈をデータ属性でまとめて並べる。ヒストグラムの棒ごとのグループ化、データ被覆による順序付け、フィルタに応じた注釈更新を行う。
- **データ属性に基づく推薦[41]：** 現在の対象と属性が近い知見を検索する。
- **Shrinivasan & Gotz[119]：** ノートに前後の操作経路を付け、現在の問いと過去の分析の関連性を推定する。
- **InsightNotes[143]：** 大量の注釈を要約で管理する。テキスト断片、クラスタ代表、件数を伴う利用者指定カテゴリなどを使い、要約を操作・伝播する問い合わせエンジンを備える。

[応用案]

知見索引を、レポート掲載順だけでなく、問い、対象、期間、指標、検証状態から引けるようにする。クラスタ要約から元の知見へ辿れるようにし、要約の作成で例外を消さない。

## 4. テキストと図の統合

[原典の整理：§4.3.4、pp.16–17]

### 自動・半自動の対応付け

- Laiら[69]は図を画像として扱い、視覚要素検出と自然言語処理で、文章と対応する強調を図内に配置。紹介された注釈精度は59%。
- Kori[70]はVega-Lite仕様から図の特徴を取り出し、文章断片と点・区間の参照を対応付ける。アルゴリズム評価は41.6%であった一方、利用者調査では使いやすさ・有用性が示唆された。
- Caiら[15]は、データと視覚要素を知識グラフにし、文章から抽出した情報をその実体に結び付ける。利用者が自動結果を修正でき、参照検出精度は59%と紹介される。

これらは対象と評価課題の異なる指標であり、単純な性能ランキングや現行LLMの精度として扱わない。自動リンクは誤るため、生成された参照を確認する必要があることが読み取れる。

### 著者・読者側の支援

VizFlow[127]では、文章断片と図の強調を手動で結び付け、スクロールで読める記事を作る。Charagraph[91]では、読者が文章や表のデータを選び、棒・折れ線・円グラフを作成・編集し、統計や複数図の組み合わせを利用する。通常のテキストリーダーとの比較で、分析課題の正答が増え負担が減った。

ほかに、ファクトを図の強調に対応付けるルール、注釈を見やすく配置するアルゴリズムがある。

[応用案]

本文の主張ごとに根拠図表を指定し、図表が主張を実際に支えているか確認する。図の自動読解や自動リンクの出力を、そのまま検証済みの証拠として扱わない。

## 5. 知見・タグ・図・データを関係構造にする

[原典の整理：§4.3.5、pp.17–18、Figure 10]

知見・概念・データ・図・タグ・コメント・出典などを、木やグラフで結ぶ。主な用途は次のとおり。

| 研究・システム | 用途・特徴 |
|---|---|
| 根本原因分析の研究[35] | 概念やインスタンス、データの関係を使って分析 |
| Gotzら[46] | 新しい概念と既存データを、地図・タイムライン等で接続 |
| Zhaoら[152] | グラフ作成過程の再生により、非同期の引き継ぎで分析の意図を理解 |
| CoVA[81] | 知見グラフをJSONで保存し、Gitで分析者間の結果を統合・競合検出 |
| Annotation Graphs[151] | コメント、タグ、データ選択をグラフ化。ノードの固定・統合で理解に合わせる |
| InsideInsights[92] | 解析パイプラインと知見を階層化し、詳細度を切り替えながら提示 |

InsideInsightsの紹介では、内容について予備知識が少ない利用者には、木構造の方がグラフより認知的負担が低いとされる。

[応用案]

内部の知見間関係はグラフ的に保持し、読者の入口には階層的な構成を用いる。全文を巨大な関係図にする必要はない。なお、Git上の競合検出と、仮説の意味上の矛盾を自動的に正しく判定することは別の問題である。

## 6. 図と知見への省察を支援する

[原典の整理：§4.3.6、p.18]

- Fanら[43]：y軸の切断・反転・縦横比によって誤解を招く折れ線図を、正しい図の注釈などで補う。
- VisuaLint[56]：負値のサイズ符号化、不適切な色、凡例の欠落、二軸図の尺度不整合、軸の切断など5つの問題を可視化する。一般利用者には、視覚的補足と文章の説明を併用するscaffoldingが必要。
- McNuttら[94]：タロットの比喩を使い、データパターンの提示に加えて、疑問を投げ掛けることで自動知見への批判・省察を促す。

[応用案]

グラフ作成後に、軸・単位・符号化・凡例・基準の確認と、「ほかの説明はないか」「この集計で消えるものは何か」の確認を設ける。タロットという表現そのものを採用する必要はない。

## 7. レポート・プレゼンテーション生成

[原典の整理：§4.3.7、pp.18–19、Figure 11]

### 7.1 基本図に注釈を重ねる

- Maldonadoら[90]：看護シミュレーションなどで、実活動のタイムラインに意味のあるルール・知見の層を重ね、説明と振り返りを支援。
- Temporal Summary Images[14]：時点別のスナップショットとタイムラインをまとめ、顕著な特徴を自動注釈。スナップショット選択、配置、属性・注目点の重みなどを利用者が調整する。
- Contextifier[58]：株式ニュースの文脈を与えるため、関連記事と株価データを検索し、データ上の顕著な特徴と記事の出来事を結び付けた時系列図を作る。
- Roslingifier[118]：時系列散布図の大きな変化をイベントとして検出し、ラベル・spotlight・軌跡で動的に示す。利用者が時間順、ラベル、文章を編集できる。

### 7.2 執筆とデータ操作を結ぶ

CrossData[28]は文章中のデータ操作を認識し、平均などの派生値を計算する。DataParticles[16]はブロック単位で記事を作り、「上位5件を強調」などの文中の属性・効果から、前のブロックを引き継いで図を作る。

VisInReport[114]の談話分析や、地理空間現象の分析[76]では、観察メモと関連図をPDFレポートへまとめ、探索と報告を接続する。

### 7.3 来歴・知見空間を介して往復する

StoryFacets[99]とGratzlら[48]は、意味のある可視化状態と操作経路を残し、そこからスライドやダッシュボードを作る。対象読者を変えて成果物を構成し、来歴を共有できる。

Chenら[24]は、知見を構造化したstory slicesとして取り出し、選択・組み合わせ・配置によって一般向けのストーリーを作る。

[応用案]

本文を書き始める前に、再利用可能な知見の単位を作る。文章の修正に伴って追加集計が必要になったら、同じデータ条件を復元して解析し、対応する知見を更新する。執筆順と探索順を同一にする必要はない。

## 8. ファクト採掘と推薦・ストーリーテリング

[原典の整理：§4.3.8、pp.19–20、Figure 12]

### 8.1 Tuple型の採掘

QuickInsights[40]では、知見型、スコア、subspace、breakdown、measureを含むtupleでファクトを表す。

| 要素 | 意味 | 原典の例に沿った解釈 |
|---|---|---|
| type | 傾向・外れ値などの種類 | 売上の年次トレンド |
| score | 型に応じた評価 | どれほど特徴的か |
| subspace | フィルタした対象 | 国＝中国 |
| breakdown | 分解軸 | 年 |
| measure | 測る量 | 売上 |

同じ構造を使い、対象・分解軸・指標を変えて系統的に候補を生成する。この型は後続の複数研究に採用・拡張された。

Tangら[129]はimpact（対象の重要性）とsignificance（珍しさ）に基づくスコアを提案した。ここでのsignificanceを、一般的な検定の統計的有意性と無条件に同一視しない。

MetaInsight[86]はcommonnessとexceptionsを分け、個別スコアを高くしつつ冗長性を抑えた集合を選ぶ。高順位のファクトを個別に並べるだけでは得られない、全体傾向と例外の組を作る考え方である。

### 8.2 計算モジュール型の採掘

DataSite[34]などは、相関、傾向等を抽出する複数の計算モジュールを用い、計算量や主要パターンに応じて実行を調整する。例として、線形関係をPearson相関係数で順位付けする研究[37]が紹介される。

Voder[125]はヒューリスティックでファクトを作り、対応する図と強調、文章テンプレートを組み合わせる。指定した図のファクト探索や、sum／averageなど構成を変えた図の推薦ができる。Boomerang[74]は対話文脈に基づき、interestingness、relevance、timelinessで知見を推薦する。

### 8.3 採掘したファクトを編集する

- CoInsight[77]：階層表からpoint・shape・compound insightを抽出し、対象範囲と表頭の階層に基づく関係グラフを構築。選択した知見を木状ストーリーとして閲覧する。
- Notable[80]：ノートブック内の指定図から6種類のファクトを抽出し、文章・強調を生成。利用者が編集・選択・並び替えし、スライドへ出力する。
- LEVA[154]：LLMでビュー仕様に基づくチュートリアル、選択データ・タスクに基づく知見推薦、利用者が選んだ分析経路のLaTeXレポートを生成する。
- InkSight[83]：図上のスケッチで関心領域を示し、対応するファクトを提案。順序、削除、グループ、編集で文章を構成する。

[応用案]

候補の収集と、読者向けの選択・編集を分離する。候補には対象と操作を付け、全体傾向と例外の組を確保する。ファクトを計算する部分と、LLMが文章にする部分を分ければ、文章生成時の数値の変質を点検しやすい。

## 9. 機械学習によるファクト・ストーリー生成

[原典の整理：§4.3.9、pp.20–22、Figure 13]

| システム | 手法・利用者の関わり | 目指すもの |
|---|---|---|
| DataShot[136] | ファクトを主題でまとめ、上位n件に図・テンプレート文章・配置を割り当てる。図選択に決定木 | 自動ファクトシート |
| Calliope[117] | elaboration、cause-effect等、定義した6種の関係に基づくMonte Carlo tree search | 一貫したストーリーと編集 |
| Calliope-Net[23] | topic–evidence–explanation構造。スコア、多様性、ネットワーク被覆を考慮 | グラフデータの注釈付き物語 |
| Erato[128] | 利用者のkey facts間を、ファクトのベクトル化と木探索で補間 | 人の意図に沿う接続 |
| Socrates[141] | 質問で好み・目的を引き出し、Pareto最適化と木探索を利用 | 複数目的に合うストーリー |
| SNIL[29] | 利用者の知見文から主題・タスクを分類し、テンプレート、図、LLM生成見出し・説明を組み合わせる | スポーツ記事のエピソード構成 |
| Sintel[1] | 異常検出パイプライン、パラメータ調整、ベンチマーク比較、専門家によるイベント確認・修正・削除 | 人の知識を使う時系列異常検出 |
| DashBot[38] | Markov decision processと深層強化学習。多様性・簡潔さ・insightfulnessを報酬化 | 平坦な表からダッシュボード |
| InsigHTable[78] | 深層強化学習で、探索と知見の量・多様性を報酬化 | 階層表に埋め込む可視化 |
| Shiら[116] | 強化学習で、統計的知見数、論理順序、注釈混雑を考慮 | 散布図への段階的な動的注釈 |

Calliopeのcause-effectは、物語をつなぐ関係の種類として紹介されている。因果推論による原因の識別が自動的に完了するという意味ではない。

Socratesは、目的を単一スコアへ潰さずに複数目的を扱う事例である。ただし、一般のAgentレポートにPareto最適化を必須とする必要はない。

### 9.1 自動化の到達点と不足

[原典の整理：§4.3.10、pp.22–23]

自動化はファクトの収集・順位付け・描画・構成の負担を下げる。利用者はkeyframes、質問への回答、知見文、編集などで方向付けられる。一方、次が不足する。

- 自動化研究の多くはデータへの知見が中心で、ドメイン情報の組み込みが弱い。
- 多くの生成はbottom-upであり、レポートから仮説を立てて解析へ戻るtop-downが十分に扱われていない。
- 主に単一利用者・デスクトップで、非同期協調は一部にとどまる。
- 単純なファクトの論理接続だけでは、読者にとっての適用可能性や意味は保証されない。

## 10. スキル設計へ移す際の対応表

[応用案]

| 論文で扱う技術 | Agent用の最小実装案 | 失われやすい点 |
|---|---|---|
| Data-aware annotation | 知見IDとデータ条件・図表参照 | 対象を文章だけにすると復元できない |
| Insight repository | Markdownの知見カード＋索引 | 掲載した結果だけ残すと選択履歴が消える |
| Graph / tree | 関係表＋階層的な目次 | 一覧だけでは反証・補完関係が見えない |
| Provenance | 実行スクリプト、パラメータ、データ版へのリンク | 画像だけでは計算根拠に戻れない |
| Fact mining | 明示した探索軸と候補台帳 | 上位結果だけでは見た範囲が分からない |
| Story authoring | 知見IDを参照するレポート本文 | 流暢な文章で根拠の境界が消える |
| Mixed initiative | 不足する文脈や判断基準だけを人に確認 | ドメイン事情をAgentが創作する |
| Top-down iteration | 草稿の疑問→追加解析の記録 | 既存の筋書きに合う証拠だけ増やす |
