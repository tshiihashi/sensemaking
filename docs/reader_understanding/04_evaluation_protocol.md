## 1. 最初に分ける評価対象

| 対象 | 観測すること | 代用してはいけない指標 |
| --- | --- | --- |
| 主観的な納得感 | 説明が筋道立っていると感じるか、判断に必要な説明があると感じるか | 結論への賛成だけで理解・正しさとしない |
| 読みやすさ | 読み進めやすさ、用語や構成で止まった箇所 | 文字数・可読性スコアだけで判断しない |
| 正確な理解 | 主張、比較条件、限界、結果間の関係を自分の言葉で説明できるか | 「分かった」という自己評価で置き換えない |
| 必要情報への到達 | 指定した根拠・反証・条件を見つけられるか、時間と誤り | クリックの有無を熟読・理解としない |
| 根拠に見合った信頼 | 正しい主張を利用し、誤りや根拠不足では修正・保留できるか | 信頼評定の高さ自体を成功としない |
| 認知負荷・作業負担 | 内容の難しさ、探索・照合の手間、努力・焦り等 | 所要時間だけで負荷を断定しない |

根拠：理解と感想の区別は[A1・A2](01_reading_and_presentation.md)、判断・主観評価の不一致は[B2・B5・B6](02_trust_and_verification.md)。上の表全体を一つの既成尺度として引用しない。

## 2. 負荷をどう測るか

### M1 Klepsch, Schmitz & Seufert (2017)

*Development and Validation of Two Instruments Measuring Intrinsic, Extraneous, and Germane Cognitive Load.* [DOI](https://doi.org/10.3389/fpsyg.2017.01997)／[掲載版HTML・Table 3](https://pmc.ncbi.nlm.nih.gov/articles/PMC5696680/)／[保存PDF](../../papers/reader_understanding/Klepsch_2017_Cognitive_Load_Instruments.pdf)。

[原典の実証結果：Studies 1〜2] 学習課題について、負荷概念を教えてから評定する方法と、概念を教えず質問紙へ答える方法を開発・検討した。Study 1は97名、Study 2は課題ごとに65〜95名。重要情報の発見や関連付けの難しさ等を、内容自体の複雑さと分けて質問する構成を持つ。

**限界。** 大学生と学習課題、主にドイツ語の質問紙の研究である。3種類の負荷を独立した量として常に正確に測定できる、とは扱わない。日本語へ翻訳し、解析レポート用に改変した質問の妥当性は別に確認する。

[応用案] 小規模試行では、内容の難しさと提示の問題を分けて聞く。尺度を使用する研究では、原文、翻訳、項目変更、採点法を明示する。

### M2 NASA Task Load Index（NASA-TLX）公式資料

[公式説明](https://www.nasa.gov/human-systems-integration-division/nasa-task-load-index-tlx/)（確認日：2026-11-06）。

[公式資料の整理：NASA Task Load Index、Paper and Pencil Version] 主観的作業負担を、精神的要求・身体的要求・時間的要求・作業成績・努力・不満の6側面で評定し、公式説明では重み付きの総合得点を用いる。利用前にマニュアルを読むよう案内している。

**適用と限界。** 文章理解専用の尺度ではなく、理解の正確さを測るものでもない。今回確認したのは公式紹介ページで、マニュアル全文・日本語版の妥当性・具体的な実施手順の照合は未実施。

[応用案] 短い初期試行には下の用途別の質問を使い、検証的な研究でTLXを採る場合はマニュアル等を追加確認する。一部の項目だけを抜き出したものや独自質問を「NASA-TLXの得点」と呼ばない。

### 小規模試行用の独自質問

各課題後に1〜7で答えてもらい、迷った箇所を自由記述する。**これはM1・M2を踏まえた独自の確認項目であり、検証済み尺度ではない。** 総合得点へ合算せず、項目別に見る。

- 内容・概念そのものは、どの程度難しかったか。
- 必要な情報を探すのに、どの程度手間がかかったか。
- 文章・図・条件を対応付けるのに、どの程度手間がかかったか。
- 根拠が主張を支えるか確かめるのに、どの程度手間がかかったか。
- 説明は、どの程度読み進めやすかったか。
- 判断に必要な説明が得られたと、どの程度感じたか。

「検証しなかったため楽だった」と「十分に検証でき、楽だった」を区別するため、必ず根拠確認課題の成績と併せる。

## 3. 初期比較の手順

### 入力の準備

同じ解析結果から、次の2版を作る。

- **A版**：普段のAgentレポート。
- **B版**：[設計案](03_report_design.md)に沿って、説明・図表の対応、条件の位置、要約と詳細の構成を調整した版。

まず**提示方式の比較**として、観察事実、数値、重要な条件、反証・代替解釈、根拠は両版で同じにする。配置や言葉を変える前に、共通の事実一覧を確定する。必要な前提説明を追加した場合も差分を記録する。情報を追加した効果と、配置だけの効果を混同しない。

別の段階で**Agentの工程全体**を比べる場合は、入力データからの見逃し、選択・解釈・数値の誤りも評価する。提示だけの比較ではAgentの解析品質を保証できない。

### 読者と割り当て

想定読者を含む少人数の形成的評価から始め、人数と経験・話題への馴染みを記録する。少人数で統計的優越性は主張しない。本格比較の人数は、主要指標と許容する差・ばらつきに基づいて後で決める。

同じ人に同じ内容のA→Bを見せると、先に読んだ内容の記憶が効く。参加者間でA/Bを割り当てるか、同程度の別ケースを用意して版と順序を釣り合わせる。画面幅・利用時間・参照可能な資料も揃える。

### 課題と観測

| 段階 | 課題例 | 記録するもの |
| --- | --- | --- |
| 概要把握 | 主な結果と、まだ言えないことを説明する | 主張の再現、条件・限界の保持、時間 |
| 横断理解 | 全体と一部条件の結果がなぜ異なるか説明する | 比較単位の誤り、関係の説明、必要な留保 |
| 代替解釈 | 同じ観察に成立する説明と、区別する追加情報を挙げる | 観察と推測の混同、根拠の差の理解 |
| 根拠確認 | 指定した主張の表・対象条件・出典箇所を見つける | 到達の成否・時間、誤った根拠への到達 |
| 判断 | この情報で何を判断でき、何を保留するか述べる | 不適切な断定・過剰な保留、理由 |
| 主観評価 | 読みやすさ・納得感・負担を答える | 項目別評定、行き詰まった場所 |

概要を見ながら答える理解課題と、資料を閉じて答える記憶課題は分ける。資料を見られる条件を統一し、時間切れ・無回答も記録する。正答者だけの時間を比較して、理解できなかった人を隠さない。

### 理解の採点案

事前に、主要主張・適用条件・横断関係・代替解釈・不確実性・根拠の6観点について、正答に必要な要素と重大な誤りを定義する。各観点0（誤り・欠落）、1（一部）、2（必要な要素を含む）とする案。**本資料独自のルーブリック**であり、標準尺度ではない。

因果関係が未確定なら、特定の仮説への同意を正解にしない。観察と推測を区別し、支持・反証・判断不能な理由を適切に扱えるかで採点する。自由記述は人が確認し、複数の採点者がいる場合は不一致とその解決も記録する。

### 過剰依存を確認する場合

正誤を確定できる説明用ケースに、正しい主張と、数値・対象条件等に誤りのある主張を用意し、隔離した評価資料として提示する。実レポートは改ざんしない。事前の正誤表を用い、次を別々に集計する。

- 誤ったAI主張を採用した率＝採用した誤主張数／提示した誤主張数。
- 正しいAI主張を適切に利用した率＝利用した正主張数／提示した正主張数。
- 根拠不足の主張で判断を保留し、その理由を示せたか。

これは単純な採否を扱う実務上の指標案で、他論文の指標名と同一だとはしない。競合仮説へ無理に正誤ラベルを付けない。回答後に正誤と根拠を説明する。

## 4. 結果と採用判断を残す形式

```markdown
## レポート比較の記録
- 入力／共通の事実・条件・証拠一覧：
- A/Bで変更した点／比較に影響する差：
- 読者数・経験・話題への馴染み／割り当てと順序：
- 参照条件・時間・画面：
- 課題・正答基準・採点者：
- 理解成績／重要な誤解／無回答：
- 根拠到達の成否・時間：
- 読みやすさ・納得感・負担の項目別結果：
- 正しい主張の利用／誤った主張の採用／適切な保留：
- 採用・修正・保留の判断と理由：
- 未実施の確認／一般化できない範囲：
```

重要な条件や例外を理解できたかを先に見て、時間・負担・主観評価の変化を続けて確認する。速く読めても誤解が増える場合、気持ちよく読めても根拠の弱い断定を信じる場合は、そのまま採用しない。時間が増えても検証が進んだ場合は、増分に見合うかを用途に照らして判断する。単一スコアで順位を固定しない。
